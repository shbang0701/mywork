# WorkTool 새 버전 (WPF) — 메모 · 문서 · 활성 작업 · 업무

지금 쓰는 WorkTool(WinForms, `apps/WorkTool/`)을 옮겨 갈 새 버전입니다.
계획과 결정 사항은 이슈 #8 「WorkTool 개편 계획 · 결정할 것」, 화면 기준은 `apps/WorkTool/design/README.md`에 있습니다.

## 1단계에 들어 있는 것

- 창 틀: 제목 줄을 직접 그린 창(최소화 · 최대화 · 닫기), 창 투명도, F11 전체 화면
- 왼쪽 메뉴: 애드온(탭) 목록으로 자동으로 만든다. 접기 · 펼치기(Ctrl+B), 아래에 설정 · 도움말
- 테마: 파스텔 7색(하늘 · 분홍 · 연두 · 노랑 · 보라 · 회색 · 검정), 창 투명도 60~100%, 글자 크기 3단계. 바꾸면 바로 반영
- 설정 화면: 테마, 메뉴에서 탭 끄기, 데이터 위치, 예전 데이터 다시 가져오기
- 예전 데이터 가져오기: 처음 실행하면 예전 WorkTool의 `data` 폴더에서 메모 · 일정 · 근태를 읽어 와서 보여 준다
- 탭: 홈(다른 탭의 카드 모음) · 일정 · 근태(**보기 전용**) · 메모 · 문서 · 활성 작업 · 업무
- 활성 작업: 실행 중인 앱 창과 Chrome·Edge·웨일 탭 제목을 프로그램별 표로 봅니다. 선택 닫기, 수동·자동 새로 고침을 지원합니다. 자세한 사용법은 아래 「활성 작업」에 있습니다.
- 업무: 스크립트 폴더의 PowerShell 스크립트를 폼으로 실행합니다. param이 입력 칸이 되고, 자주 쓰는 값은 업무로 저장합니다. 자세한 사용법은 아래 「업무」에 있습니다.
- 문서: [폴더 추가]로 고른 폴더(공유 폴더도 됨)를 왼쪽 트리로, 오른쪽에 파일 목록(이름 · 종류 · 고친 날짜 · 크기, 이름으로 거르기). 두 번 클릭 · Enter · [열기]는 원래 프로그램으로 열고, 폴더면 들어간다. 실행 파일(.exe · .ps1 · .bat …)은 한 번 묻는다. [폴더에서 보기] · [경로 복사] · [즐겨찾기] (홈 카드에도 보임). 폴더 목록 · 즐겨찾기는 데이터 폴더의 `settings.json`에만 저장한다(저장소에 올라가지 않음). 마지막으로 본 폴더를 열 수 없으면 첫 폴더를 연다. 파일 내용은 읽거나 옮기지 않는다
- 메모: Obsidian처럼 그린 글 위에서 바로 고친다(고치는 블록만 원문). 원문 · 읽기 모드, 열어 둔 메모 탭, 오른쪽에 나눠 두 칸, 빠른 이동(Ctrl+O), `[[` 메모 링크 자동 완성, 찾기 · 바꾸기, 자동 저장, 삭제 후 10초 동안 실행 취소. 제목을 비우면 저장 시각이 제목. 본문의 `#태그`는 `tags`에 모은다. 자세한 것은 아래 「메모」
- 마크다운 보기: 문법 예시는 도움말 → 마크다운. 자세한 것은 아래 「마크다운 보기」
- 창의 X는 앱을 끝낸다. 설정 → 닫기 버튼에서 「트레이로 숨기기」를 고르면 트레이에 남고, 끄려면 트레이 아이콘 우클릭 → 종료
- 아이콘: 강조색 둥근 사각형에 W. 제목 줄 왼쪽 · 작업 표시줄 · 트레이에 같은 모양으로 보이고, 테마 색을 바꾸면 같이 바뀐다

일정 · 근태 편집, 알람, 지금 출근, 메모별 잠금은 2단계에서 옮깁니다. 그때까지는 예전 WorkTool을 계속 쓰세요.
새 버전에서 쓴 메모는 예전 WorkTool에 보이지 않고, 설정의 「다시 가져오기」를 누르면 메모는 예전 데이터로 덮어씁니다(직전 파일은 `.bak`). 일정 · 근태는 덮어쓰지 않고 합칩니다(새 줄은 더하고, 새 버전에서 고치거나 지운 것은 그대로). 규칙은 [일정 · 근태 데이터 설계](../../../docs/plans/schedule-attendance-design.md) 7장에 있습니다.

## 개인 PC에서 실행하기

**저장소를 받아 둔 PC**(`git clone`)는 zip이 필요 없습니다. `apps/WorkTool/wpf/start-dev.cmd`를 더블클릭하면 이 폴더의 원본을 바로 띄우므로, 고친 내용이 바로 보입니다. 바탕 화면에 바로 가기를 만들어 두면 편합니다.
- 데이터는 zip으로 띄울 때와 같은 곳(문서\WorkTool)을 써서 메모 · 설정이 그대로 보입니다. 둘을 함께 띄우면 나중 것은 중복 실행으로 막힙니다.
- 작업 중인 브랜치를 미리 보려면 그 브랜치로 바꾼 뒤 띄웁니다.

**저장소가 없는 PC**는 저장소 맨 위 `worktool.zip`을 받아 우클릭 → 속성 → 「차단 해제」 체크 → 압축을 풀고 `Start-WorkTool.cmd`를 더블클릭합니다. 실행 보조 창은 바로 닫히고 GUI만 남습니다. `.cmd`의 초기 창이 잠깐 보일 수는 있습니다.
- 압축 안의 `WorkTool-WPF.ps1`, `Start-WorkTool.cmd`, `Start-WorkTool-Launcher.ps1` 세 파일과 `scripts` 폴더를 같은 폴더에 둡니다. `scripts`에는 저장소 `scripts/`의 예제 스크립트가 들어 있어서, 켜면 업무 탭의 「예제 스크립트」에 바로 보입니다. 필요 없으면 `scripts` 폴더는 지워도 됩니다. 시작 검사에 실패하면 실행 창에 오류를 표시합니다. 실행 정책은 바꾸지 않습니다.
- 작은 W 배지 대신 창의 전체 아이콘을 적용합니다. Windows 작업 표시줄의 기존 고정 아이콘·PowerShell 묶음은 시스템 설정에 따라 PowerShell 모양으로 남을 수 있습니다.
zip은 `build/Build-Bundle.ps1`이 묶음 파일과 같이 만듭니다.

## 업무 PC에서 실행하기

1. `apps/WorkTool/dist/WorkTool-WPF.ps1`을 복사해서, 예전 WorkTool 폴더(예전 `data` 폴더가 있는 곳)에 같은 이름으로 저장합니다.
2. `pwsh`에서 `.\WorkTool-WPF.ps1`로 실행합니다.
3. 확인할 것
   - 창이 뜨고, 왼쪽 메뉴에 홈 · 일정 · 근태 · 메모가 보이는지
   - 탭 위에 마우스를 올리거나 다른 앱과 오가도 PC가 버벅이지 않는지
   - 홈 · 일정 · 근태 · 메모에 예전 데이터가 보이는지
   - 설정에서 색 · 글자 크기를 바꾸면 바로 바뀌는지. 투명도는 100%와 그 아래를 오가면 다시 시작한 뒤 바뀌는지(설정 화면에 안내가 뜸)
   - 최대화 · F11 · Ctrl+B · X로 끝내기 (설정에서 트레이로 숨기기를 고르면 트레이에서 종료)
   - 도움말 → 마크다운: 코드 블록 [복사], 접는 콜아웃 펼치기, 다이어그램, 보기 | 원문 바꾸기
   - 메모: 본문이 마크다운으로 보이는지, `[[다른 메모 제목]]` · `#태그`를 누르면 그 메모 · 검색으로 가는지
   - 메모 고치기: 그린 글을 누르면 그 블록만 원문이 되는지, ↑↓로 블록 사이를 오가는지, 한글을 칠 때 글자가 끊기거나 사라지지 않는지, Ctrl+B · Enter(목록 이어 쓰기) · `[[` 자동 완성
   - 메모 쓰기: 새 메모 → 제목 · 본문 입력 → 「자동 저장됨」 표시, 앱을 껐다 켜도 남는지(열어 둔 탭 포함), 삭제 → 실행 취소, 탭 · Ctrl+\ 나눠 보기
   - 문서: 폴더 추가(공유 폴더 포함) → 트리 펼치기 · 파일 두 번 클릭으로 열기(DRM 문서 포함) · 즐겨찾기 → 홈 카드에서 바로 열기
   - 활성 작업: 표의 창·탭 확인 → 새로 고침 우클릭 → 자동 → 1분 적용 → 목록 갱신. 닫기 검사는 먼저 저장한 테스트 문서나 빈 탭으로 확인
   - 업무: 저장소 `scripts/`의 스크립트를 `문서\WorkTool\scripts`에 복사 → F5 → 「내 스크립트」에서 `Get-DiskSpace` [실행] → 표 · 「성공」 확인. `Watch-MultiPing` 고르기 → 콘솔 창에서 [실행] → 그 창에서 Q로 끝내고 요약 CSV 확인. 앱 안 실행은 `Rounds` 칸에 3을 넣고 [실행] → 출력 · 「성공」 확인

오류가 나면 창에 뜬 문구(또는 콘솔의 빨간 글씨)를 그대로 알려 주세요.

- "STA 모드에서 실행해야 합니다"가 나오면 `pwsh -STA -File .\WorkTool-WPF.ps1`로 실행합니다.
- 예전 데이터를 못 찾으면 설정 → 데이터 → 「위치 고르기」에서 예전 `data` 폴더를 고릅니다.

## 활성 작업

앱 창과 Chrome·Edge·웨일 탭 제목을 **프로그램별 표**로 보여 줍니다. 실행하지 않은 작업 표시줄 고정 아이콘, 백그라운드 프로세스, WorkTool 자체 창은 대상이 아닙니다. 관리자 권한 앱이나 보안 프로그램이 정보를 제한하는 창은 읽거나 닫지 못할 수 있습니다.

WorkTool을 띄운 터미널(Windows Terminal · PowerShell 창 · VS Code 등)은 표에 `WorkTool 실행 중`으로 보이지만 닫지 않습니다. 그 창을 닫으면 WorkTool도 함께 꺼지기 때문입니다.

**찾기와 선택**
- 이름 검색(Ctrl+F), 프로그램 필터, 열 머리글 정렬을 지원합니다. 프로그램 묶음을 접고 펼칠 수 있습니다.
- 행의 체크박스로 닫을 대상을 고릅니다. 그룹 체크는 현재 검색·필터에 포함된 항목만 대상으로 합니다. 닫기를 지원하지 않는 행은 체크할 수 없습니다.
- 같은 창 안의 동일 제목 탭은 `(탭 2)`처럼 순서를 덧붙입니다. 새로 고침할 때는 제목 대신 창·탭 식별자로 체크와 접기 상태를 유지합니다. 검색·필터를 바꾸면 체크를 해제합니다.

**수동·자동 새로 고침**
1. [새로 고침]을 왼쪽 클릭하거나 F5를 누르면 한 번 수집합니다.
2. 버튼을 우클릭하면 [수동] · [자동…]이 나옵니다. 키보드는 버튼에 포커스를 둔 뒤 Shift+F10입니다.
3. [자동…]을 고르면 분 입력 대화상자가 열립니다. 처음 제안값은 **5분**, 범위는 **1~1,440분의 정수**입니다. [적용]을 눌러야 모드와 간격이 바뀝니다. 취소·Esc·창 닫기는 기존 설정을 유지합니다.
4. [수동]을 고르면 자동 갱신을 멈추고 마지막 간격은 기억합니다. 현재 모드는 버튼 옆에 표시합니다.

기본 모드는 수동입니다. 모드·간격은 로컬 `settings.json`의 `tasks.refresh`에 저장해 재실행해도 유지합니다. 자동 모드에서도 버튼 클릭과 F5는 사용할 수 있습니다. 활성 작업 탭이 보이고 앱 창이 최소화·트레이 숨김 상태가 아닐 때만 자동 수집합니다. 설정·닫기 확인창이 열려 있거나 이미 수집/닫기를 처리 중이면 새 작업을 겹쳐 시작하지 않습니다. 자동 간격은 수집이 끝난 시점부터 셉니다.

**선택 닫기**
- [선택 닫기]에서 대상 목록을 확인한 뒤 [닫기]를 누릅니다. 창·탭의 식별자와 제목이 바뀌었으면 건너뜁니다.
- 원래 프로그램의 일반 닫기 기능을 요청합니다. 저장 확인·페이지 이탈 확인은 원래 프로그램에서 직접 처리하세요. 강제 종료, 자동 저장, 자동 「저장 안 함」 선택은 하지 않습니다.
- 결과는 닫힘 · 이미 없음 · 확인 필요 · 실패 · 취소로 표시합니다. 결과에 마우스를 올리면 항목별 사유를 볼 수 있습니다. 닫힘을 확인하지 못하면 완료로 표시하지 않습니다.
- [취소]는 다음 항목부터 중단합니다. 이미 보낸 닫기 요청을 되돌리지는 않습니다. 응답이 느린 프로그램의 현재 요청은 반환될 때까지 기다릴 수 있습니다.

**지원 범위와 검사**
- PowerShell과 Windows 기본 .NET UI Automation만 씁니다. 추가 앱·모듈·확장 프로그램·디버깅 포트는 필요 없습니다. 브라우저 프로필·방문 기록·페이지 본문을 읽지 않고, 수집한 제목을 파일에 저장하지 않습니다.
- 수집은 창을 복원하거나 탭을 전환하지 않습니다. 브라우저가 정보를 내주지 않으면 `탭 확인 불가` 또는 `일부 탭 확인 불가`로 표시합니다. 브라우저 창 전체 닫기로 대신하지 않습니다.
- 웨일은 Chrome과 같은 방식으로 탭을 읽습니다. 실제 웨일에서는 아직 확인하지 않았으며, 탭을 못 읽으면 `탭 확인 불가`로 둡니다.
- 브라우저는 UI Automation으로 탭을 읽으면 접근성 기능을 켜서 메모리를 조금 더 쓸 수 있습니다. 보안 프로그램이 다른 앱 화면을 읽는 동작으로 볼 수도 있으니, 자동 새로 고침은 업무 PC에서 한 번 확인한 뒤 켜세요.
- `addons/active-tasks/Test-ActiveTasks.ps1`은 임시 데이터와 전용 테스트 창만 씁니다. 코어 검사가 찾아서 돌리며, Windows STA에서는 실제 그룹 체크·모달·타이머 경로와 UIA 닫기까지 검사합니다.
- 설치된 브라우저를 추가로 검사하려면 해당 실행 파일을 `-BrowserPath`로 명시합니다. 새 임시 프로필의 가짜 페이지 두 개만 열고 기존 프로필을 사용하지 않습니다. 브라우저 첫 시작 정책으로 테스트 프로필 실행이 막히면 제한을 우회하지 않습니다.
- 업무 PC의 DRM 앱과 보안 정책은 환경마다 다릅니다. 해당 환경에서도 정상 동작한다고 미리 보장하지 않습니다.

## 업무

스크립트 폴더의 PowerShell 스크립트를 폼으로 실행합니다. 업무 기능은 앱이 아니라 스크립트로 더하므로, 새 기능은 스크립트 파일 하나를 폴더에 넣으면 됩니다. 설계와 스크립트 약속은 [업무 탭 설계](../../../docs/plans/workflows-design.md), 화면은 [디자인 README의 업무](../design/README.md#업무-실제-화면)에 있습니다.

1. 왼쪽 목록에는 처음부터 「내 스크립트」(데이터 폴더의 `scripts`, 기본 `문서\WorkTool\scripts`)가 있습니다. 그 폴더에 `.ps1`을 복사해 넣고 F5를 누르면 보입니다. 앱 옆에 `scripts` 폴더가 있으면(zip을 푼 경우, 원본으로 띄우면 저장소 `scripts/`) 「예제 스크립트」도 보입니다. 다른 폴더는 [폴더 추가]로 더합니다. 하위 폴더 3단계까지 `.ps1`을 찾고, 이름이 `_`로 시작하는 파일은 뺍니다. 기본 폴더도 [목록에서 빼기]로 뺄 수 있고, 뺀 것은 다시 생기지 않습니다.
2. 왼쪽에서 스크립트를 고르면 param이 입력 칸이 됩니다. 칸 설명은 `.PARAMETER`, 없으면 param 줄 끝 주석입니다. 비운 칸은 넘기지 않아서 스크립트 기본값(설정 블록 값)을 씁니다.
3. [실행]은 고른 실행 방식으로 돌립니다.
   - 앱 안에서: 창 없이 돌리고 출력을 아래 칸에 보여 줍니다. [취소]는 자식 프로세스까지 끝냅니다. 이때 스크립트의 마무리 처리(`finally`)는 돌지 않을 수 있습니다.
   - 콘솔 창에서: 보이는 PowerShell 창을 띄웁니다. 끝나도 창이 남고, 사용자가 닫습니다. 도움말 `.NOTES`에 `WorkTool: 콘솔`이 있는 스크립트(`Watch-MultiPing.ps1` 등)는 이 방식이 기본입니다.
   - [미리보기]는 `-WhatIf`를 붙여 할 일만 보여 줍니다(`SupportsShouldProcess` 스크립트만).
4. 자주 쓰는 값과 실행 방식은 [업무로 저장]합니다. 저장한 업무는 왼쪽 맨 위와 홈 카드에 보입니다. [업무 삭제]는 바로 지우고 [실행 취소]로 되돌립니다.

- 실행 기록은 모든 스크립트를 합쳐 최근 100건을 둡니다. 오른쪽 「최근 실행」에서 기록을 누르면 그때 출력의 마지막 40줄을 출력 칸에 다시 보여 줍니다. 콘솔 창 실행은 출력을 남기지 않습니다.
- 앱을 끄면 앱 안 실행도 멈춥니다(창 없는 프로세스를 남기지 않음). 콘솔 창은 따로 도는 창이라 그대로 둡니다.
- 실행 정책은 바꾸지 않습니다. 정책에 막히면 그 오류가 출력에 보이고 결과는 「실패」입니다. 스크립트는 실행하지 않고 구문만 읽어서 폼을 만듭니다.
- 비밀 값(이름에 Password · Token 등이 들어간 param)과 폼에 넣을 수 없는 종류(`[string[]]` 등)는 칸이 생기지 않습니다. 그런 값이 필수이면 콘솔 창에서만 실행하고, 창에서 PowerShell이 직접 묻습니다.
- F5: 스크립트 목록 새로 고침. 다른 탭에 다녀와도 고치던 칸 값은 그대로 둡니다.
- 창이 좁으면(메뉴를 펼친 기본 창 크기 포함) 오른쪽 설명은 접혀 있습니다. [설명 펼치기]를 누르면 가운데 위에 겹쳐 뜨고, [접기]나 Esc로 닫습니다.

## 메모

Obsidian과 비슷하게 씁니다. 단축키 전체는 도움말(F1) → 「단축키」에 있습니다.

**보기 세 가지** (오른쪽 위 나눔 버튼, 모든 칸에 같이 적용)

| 보기 | 하는 일 | 단축키 |
|---|---|---|
| 편집 | 그린 글 위에서 바로 고칩니다. 커서가 들어간 블록(문단 · 제목 · 목록 항목 · 코드 블록 · 표 등)만 원문으로 바뀌고, 나머지는 그린 모양 그대로입니다 | Ctrl+E로 읽기와 오감 |
| 원문 | 마크다운 그대로(```` ``` ```` · `**` 등)를 고칩니다 | Ctrl+/로 편집과 오감 |
| 읽기 | 고칠 수 없게 그린 글만 봅니다. 할 일 체크 표시는 누를 수 있습니다 | Ctrl+E |

- 편집 보기에서 ↑ ↓ ← →는 블록 끝에서 옆 블록으로 넘어갑니다. Shift+↑↓ · Shift+클릭 · 끌기로 여러 블록을 고르면 고른 만큼 원문이 됩니다. Ctrl+A는 글 전체를 원문으로 엽니다.
- 블록 끝에서 Backspace · Delete를 누르면 옆 블록과 잇습니다.
- 고치는 블록 안의 굵게 · 링크 같은 기호는 그 블록을 나갈 때 그린 모양이 됩니다.
- Enter로 새 블록을 시작하면(제목 · 목록 항목 · 코드 블록 다음 줄 등) 앞 블록은 바로 그린 모양이 되고, 커서가 있는 블록만 원문으로 남습니다. 빈 줄을 누르면 그 빈 줄만 원문이 됩니다.

**탭 · 칸**
- 목록을 누르면 지금 탭에서 엽니다. 그 칸에 이미 열린 탭이 있으면 그 탭으로 갑니다.
- 새 탭에서 열려면 Ctrl+클릭 · 가운데 클릭, 또는 우클릭 → [새 탭에서 열기]를 씁니다.
- Ctrl+\ 또는 탭 우클릭 → [오른쪽에 나눠 열기]로 두 칸이 됩니다. 경계를 끌어 폭을 바꿉니다. 둘째 칸의 탭을 다 닫으면 한 칸으로 돌아갑니다.
- 열어 둔 탭 · 칸 · 폭은 다시 켜도 그대로입니다(설정 `memo.tabs`).

**링크**
- `[[`를 치면 메모 제목 자동 완성이 뜹니다. ↑↓로 고르고 Enter · Tab으로 넣습니다. Esc는 닫기입니다.
- `[[제목]]`을 누르면 그 메모로 갑니다. 없는 제목이면 그 제목으로 새 메모를 만듭니다. Ctrl+클릭은 새 탭, Ctrl+Alt+클릭은 다른 칸에서 엽니다.
- 파일 · 폴더 경로를 붙여넣거나 탐색기에서 끌어 놓으면 `[이름](<C:/경로>)` 링크가 됩니다. 폴더인지 파일인지는 누를 때 확인합니다. 바꾸지 않고 붙여넣으려면 Ctrl+Shift+V를 씁니다.
- 글을 고르고 URL을 붙여넣으면 `[고른 글](URL)`이 됩니다.

**저장 · 실행 취소 · 긴 메모**
- 자동 저장은 입력을 멈추고 0.8초 뒤, 다른 메모 · 탭으로 옮길 때, 끌 때 합니다. 칸마다 저장 상태가 보입니다.
- 편집 보기의 실행 취소(Ctrl+Z · Ctrl+Y)는 블록을 옮겨 다녀도 이어집니다. 잠깐 쉬었다 친 글은 따로 되돌립니다.
- 긴 메모는 화면 앞부분을 먼저 그리고, 나머지는 입력을 막지 않게 조금씩 그립니다. 고친 뒤에는 그 블록과 같은 목록 · 붙은 이웃 블록만 다시 그립니다.
- 읽기 보기의 찾기는 굵게 · 링크 등으로 모양이 나뉜 곳에 걸친 글은 찾지 못합니다. 편집 · 원문 보기에서는 찾습니다.

## 데이터

- 업데이트할 때는 기존 창과 트레이의 WorkTool을 모두 종료한 뒤 파일을 바꾸세요. 같은 데이터 폴더를 쓰는 새 실행본끼리는 중복 실행을 막습니다. `.worktool.lock` 파일이 남아도 정상이며, 앱이 끝나면 잠금은 풀립니다.
- 메모를 저장하지 못해도(파일 잠금 · 폴더 쓰기 권한 · 데이터 폴더 응답 없음) 고친 내용은 앱이 가지고 있습니다. 칸에 「저장하지 못했습니다」가 보이고 알림 창으로 한 번 알립니다. 다른 메모로 옮겨도 고친 내용은 그대로입니다. 문제를 해결한 뒤 Ctrl+S로 다시 저장하세요. 끝낼 때 아직 쓰지 못한 내용이 있으면 [다시 시도] · [끝내기] · [취소]를 묻고, [끝내기]를 고르면 그 내용은 사라집니다. 강제 종료·전원 차단 때 아직 저장하지 않은 글까지 복구하는 기능은 아닙니다.
- 문서·메모 목록은 보이는 행만 만듭니다.
- 공유 폴더(UNC · 네트워크 드라이브)가 응답하지 않아도 화면은 멈추지 않고, 창을 닫으면 앱 프로세스가 끝납니다. 디스크 · 네트워크에 닿는 일은 모두 화면 밖에서 하고, 정해진 시간까지만 기다립니다.
  - 문서 폴더 · 즐겨찾기 · 업무 스크립트 폴더: 로컬 폴더는 바로 보입니다. 답이 늦으면 「불러오는 중…」(문서) · 「읽는 중…」(업무)으로 두었다가 답이 오면 채웁니다. 업무 스크립트 폴더 · 스크립트는 10초 안에 답이 없으면 「응답 없음」으로 바뀝니다. 문서 조회는 [취소]로 결과 반영을 취소할 수 있고, 취소했거나 다른 폴더로 옮긴 조회는 기다리지 않고 새 조회를 바로 시작합니다.
  - 파일 · 폴더 열기(문서 탭 · 마크다운 링크 · 설정의 「폴더 열기」): 5초 안에 답이 없으면 알립니다.
    - 있는지 · 폴더인지 확인하는 중이었으면 「경로가 응답하지 않습니다」를 알리고, 늦게 답이 와도 열지 않습니다.
    - 확인은 끝나 Windows에 열기를 넘긴 뒤였으면(연결 프로그램이 늦게 뜨는 경우) 「응답이 오면 늦게 열릴 수 있습니다」를 알립니다. Windows에 넘긴 열기는 앱이 멈출 수 없습니다.
  - 데이터 폴더(`datapath.txt`로 공유 폴더를 고른 경우):
    - 읽기는 5초까지만 기다리고 실패로 알립니다. 그 폴더에 답 없는 읽기가 남아 있는 동안은 기다리지 않고 바로 실패합니다.
    - 저장은 화면이 0.4초만 기다립니다. 저장 요청은 들어온 순간 앱이 받아들인 내용이 되고, 파일에 쓰였다고 확인되거나 실패해서 앱이 가지고 있거나 둘 중 하나로만 끝납니다. 바로 실패해도 · 쓰기를 시작하지 못해도 · 늦게 실패해도 같습니다.
    - 0.4초 안에 끝나지 않아도 실패가 아닙니다. 앱이 들어온 차례대로 이어서 씁니다(같은 파일은 마지막 내용만). 읽기와 따로 쓰므로, 답 없는 읽기가 많이 남아도 저장은 막히지 않습니다.
    - 저장 상태는 시간이 아니라 「앱이 받아들인 내용이 파일에 쓰였는지」로 정합니다. 쓰는 중이면 「저장하는 중」, 쓰이면 「자동 저장됨」입니다. 쓰기가 늘 0.4초보다 오래 걸려도 한 번 쓰이면 「자동 저장됨」이 되고, 같은 내용을 되풀이해 쓰지 않습니다. 5초가 넘으면 「응답 없음」으로 보이지만 실패로 정하지 않습니다.
    - 쓰는 중이거나 쓰지 못한 파일을 읽으면 앱이 가진 내용이 나옵니다. 그래서 화면을 옮기거나 다시 들어와도 고친 내용이 그대로 보입니다.
    - 실패하면 그 내용을 버리지 않고 앱이 가지고 있습니다(설정 · 메모 · 업무 · 실행 기록 모두). 알림 창으로 한 번 알리고, 메모 칸에는 「저장하지 못했습니다」가 보입니다. 메모는 Ctrl+S로 다시 쓰고, 그 파일을 다시 저장하면(설정 · 업무 등) 새 내용과 함께 씁니다.
    - 끝낼 때 쓰는 중인 것이 있으면 「저장하는 중입니다」 창(응답 없음 · 걸린 초 · 남은 저장 수)을 띄웁니다. 다 쓰면 창이 저절로 닫히고 이어서 끝냅니다. 쓰지 못하고 남은 내용이 있으면 [다시 시도] · [끝내기] · [취소]를 묻습니다. [저장을 기다리지 않고 끝내기] · [끝내기]를 고를 때만 그 내용을 버립니다. 쓰던 임시 파일만 버려지고 원래 파일은 그대로입니다.
    - 켤 때 데이터 폴더가 답하지 않으면 5초 뒤 시작 오류를 알리고 끝납니다.
  - 업무 탭 실행: 시작을 기다리는 사이 [취소]하거나 앱을 끄거나 시작이 시간 초과되면, 늦게 만들어진 프로세스는 만든 쪽이 바로 끝냅니다. 만들어졌지만 화면이 아직 넘겨받지 않은 프로세스도 같습니다. 끝낼 때 스크립트가 남긴 자식 찾기는 화면 밖에서 하고 2초까지만 기다립니다. 이 정리는 작업 수 한도와 따로 돌아서, 응답 없는 조회가 많이 남아도 막히지 않습니다.
  - 같은 공유(`\\서버\공유`, 또는 드라이브 문자)에 답 없는 요청이 남아 있으면 그 공유에는 새로 묻지 않고 바로 알립니다. 같은 곳을 또 기다리지 않으려는 것이고, 남은 요청에 답이 오면 다시 묻습니다.
  - 남는 것: 파일 · 폴더 선택 창(Windows 기본 창) 안에서 응답 없는 공유로 옮겨 가면 그 창은 Windows가 기다립니다. 앱은 선택 창의 처음 폴더를 1.5초 안에 확인된 것만 넘깁니다. 선택 창은 앱 창에 붙은 모달 창이라, 다른 스레드로 옮기면 창 순서 · 포커스가 어긋나서 그대로 둡니다.
- 새 버전 데이터는 앱 폴더 밖, **문서\WorkTool**에 저장합니다. 앱 파일을 새로 덮어써도 데이터는 그대로입니다.
  - 위치를 바꾸려면 앱 파일 옆에 `datapath.txt`를 만들고 첫 줄에 경로를 적습니다.
- 파일: `memo.json` · `schedule.json` · `attendance.json` · `holidays.json`(휴무일, 일정 · 근태가 같이 씀) · `workflows.json`(저장한 업무) · `workflow-runs.json`(실행 기록) · `settings.json`. 저장할 때마다 직전 파일을 `.bak`으로 하나 남깁니다.
- 폴더: `scripts`(업무 탭의 「내 스크립트」). 사용자가 넣은 스크립트를 두는 곳이고, 앱은 폴더만 만들고 안의 파일을 바꾸지 않습니다.
- 각 파일에 `schema` 번호가 있습니다. 형식이 바뀌면 읽을 때 자동으로 변환하고, 변환 전 원본은 `<이름>.json.schema<번호>.<날짜-시각>.bak`으로 남깁니다(덮어쓰지 않음). 변환에 실패하면 원본을 건드리지 않고 그 탭에 이유를 보여 줍니다. 더 새 버전이 쓴 파일(높은 `schema`)은 읽지 않고 바꾸지도 않습니다.
- 이 버전이 모르는 칸 · 값(더 새 버전이 더한 것)은 지우지 않고 저장할 때 그대로 둡니다. 모르는 값이 든 일정 · 근태 항목은 「새 버전에서 만든 항목」, 날짜를 못 읽는 항목은 「고칠 항목」으로 따로 보이고 계산에서 빠집니다. 형식 전체는 [일정 · 근태 데이터 설계](../../../docs/plans/schedule-attendance-design.md)에 있습니다.
- `settings.json`에는 기본값과 다른 설정만 저장합니다.
- 예전 WorkTool의 CSV는 읽기만 하고 바꾸지 않습니다. Excel에서 다시 저장해 CP949가 된 CSV · 바뀐 날짜 모양(2026/10/1 · 9:30)도 읽습니다.

## 탭(애드온) 더하기 · 빼기

탭 하나를 더하거나 빼는 일은 `addons/<이름>/` 폴더 하나로 끝납니다. 코어 · 다른 탭 · 검사 목록 · 묶음 만들기는 고치지 않습니다.

- **더하기**: `addons/<이름>/<이름>.psm1`을 만들고 맨 아래에서 `Register-WtAddon`을 부릅니다. 메뉴 · 홈 카드 · 도움말 · 예전 데이터 가져오기가 저절로 연결됩니다.

  ```powershell
  Register-WtAddon -Id 'files' -Title '문서' -Icon 0xE8B7 -Order 50 `
      -NewView { New-WtFilesView } `
      -Refresh { param($view) Update-WtFilesView } `
      -HomeCard { New-WtFilesHomeCard } `
      -Help '문서는 고른 폴더의 파일을 보고 원래 프로그램으로 엽니다.' `
      -Shortcuts @(@('F5', '새로 고침'), @('Ctrl + F', '이름으로 거르기'))
  ```
  - `-Help`는 도움말 「이 버전」 문단, `-Shortcuts`는 「단축키」 줄이 됩니다. 키와 설명이 다른 탭과 같으면 `문서 · 활성 작업: 새로 고침`처럼 한 줄로 묶입니다. 키 처리 자체는 탭 화면이 합니다.
  - 도움말에 카드를 따로 두려면 `-HelpCard { ... }`로 카드 요소를 돌려줍니다 (메모의 마크다운 예시).
  - `-WarmUp`은 미리 만들기 후보를 등록합니다. 기본 실행에서는 미리 만들지 않습니다. 진단 세션에 `WORKTOOL_WARMUP=1`을 준 경우에만, 비활성 창에서 한 번씩 만듭니다.
    - `-WarmUp Full`: `-NewView`와 `-Refresh`까지 미리 부릅니다. `-Refresh`가 그 탭의 데이터 파일만 읽을 때 씁니다(일정 · 근태 · 메모).
    - `-WarmUp View`: `-NewView`만 미리 부릅니다. `-Refresh`가 폴더 조회 · 다른 창 읽기처럼 느리거나 앱 밖에 닿을 때 씁니다(문서 · 활성 작업 · 업무).
    - 주지 않으면 처음 누를 때 만듭니다. 미리 만들 때 `-NewView`는 화면 요소만 만들고, 조회 · 타이머 시작은 `-Refresh`나 화면이 보일 때로 미룹니다.
  - 검사는 같은 폴더의 `Test-<이름>.ps1`에 둡니다. 맨 위에서 `tests/TestKit.ps1`을 점 소싱하고 `Import-WtTestCore` → 자기 모듈 불러오기 → `New-WtTestData`로 임시 데이터를 만듭니다. `tests/Test-Core.ps1`이 찾아서 돌리고, 묶음 파일에는 들어가지 않습니다.
- **빼기**: 그 폴더를 지웁니다. 그 탭의 도움말 · 단축키 · 검사도 같이 빠지고, 다른 탭과 데이터는 그대로입니다. 잠깐 숨기기만 하려면 설정 → 메뉴에서 끕니다.
- 코어 코드와 코어 검사에는 특정 탭의 이름 · 설명 · 단축키를 쓰지 않습니다. 탭이 필요한 코어 검사는 가짜 탭을 등록해서 합니다.
  - 예외 1: 모양(스타일)은 `core/Ui.psm1`에만 둡니다. 탭에 새 모양이 필요하면 그곳에 쓰임새 이름으로 더합니다.
  - 예외 2: 예전 WorkTool(WinForms) 데이터 폴더를 알아보는 CSV 이름(`memo.csv` 등)입니다. 이미 정해진 예전 형식이라서입니다.
- 화면은 `core/Ui.psm1`의 `New-Wt*` 함수와 스타일 이름만 써서 만듭니다. 색 값이나 글꼴 이름을 직접 쓰지 않습니다.
- 저장은 `Get-WtStoreItems` · `Write-WtStore`만 씁니다. 형식을 바꿀 때는 `-Schema`를 올리고 `-Migrate`로 변환을 줍니다.
  - `-Schema`는 옛 버전이 잘못 읽게 되는 변경에만 올립니다. 칸을 더하는 것은 올리지 않습니다. 읽은 항목 객체를 그대로 두고 아는 칸만 고쳐서 저장하면 모르는 칸이 남습니다(아는 칸만으로 새 객체를 만들지 않습니다). 규칙 전체는 [일정 · 근태 데이터 설계](../../../docs/plans/schedule-attendance-design.md) 1장.
  - 날짜 · 시각 모양, 지운 표시, 예전 데이터 합치기 같은 형식 도우미는 `core/Records.psm1`에 있습니다(`Get-WtStamp` · `ConvertFrom-WtDateText` · `Test-WtDeleted` · `Merge-WtLegacyItems` 등). 칸이 없을 수 있는 `count`는 `$obj.count` 대신 `Get-WtField $obj 'count'`로 읽습니다(PowerShell이 붙인 Count가 나옴).
  - 형식이 있는 탭은 데이터 모듈(화면 없음)과 화면 모듈을 나누고, 고정 시험 자료를 탭 폴더 `fixtures/`에 둡니다(일정 · 근태 참고).
  - `Write-WtStore`는 쓰기 실패로 예외를 올리지 않습니다. 넣은 내용은 저장 통로가 파일에 쓰일 때까지 가지고 있고, 실패하면 다시 시도하거나 사용자가 버리기를 고를 때까지 둡니다. 바로 실패 · 쓰기 시작 실패 · 늦은 실패가 모두 같은 길(`Set-WtDataWriteFailed`)로 남습니다. 탭은 저장한 내용대로 상태를 바꾸고, 따로 다시 저장하지 않습니다.
  - 저장 표시는 시간으로 정하지 않고 `Get-WtDataWriteStatus (Get-WtStorePath $name)`의 `State`(saved · writing · failed)로 정합니다. 바뀌면 `Register-WtDataWriteHandler { param($path, $state) ... }`가 불립니다. 쓰지 못한 내용을 다시 쓰려면 `Resume-WtDataWrites $path`(메모 탭의 Ctrl+S 참고). 끝낼 때 묻는 것은 셸이 합니다.
- 이벤트 처리기 안에서는 `$script:` 변수와 보낸 요소(`$s`)의 `Tag`만 씁니다. 처리기는 나중에 불리므로, 만든 함수의 지역 변수는 보이지 않습니다.
- 셸 단축키(Ctrl+B 메뉴 접기)를 화면 안 칸이 대신 쓰려면 `Register-WtKeyOwner $칸 'Ctrl+B'`를 부릅니다. 그 칸(또는 그 안)에 포커스가 있을 때만 셸이 키를 넘깁니다. 메모 편집 칸은 Ctrl+B를 굵게로 씁니다.
- 탭 폴더 하나에 `.psm1`이 여럿이어도 됩니다(메모). 앱은 폴더의 `.psm1`을 모두 불러오고, `Register-WtAddon`은 그중 하나에서만 부릅니다.
- 디스크 · 네트워크에 닿는 일(사용자 · 저장 데이터에서 온 경로의 조회 · 읽기 · 열기)과 다른 앱에 묻는 일은 화면 스레드에서 하지 않고 `core/Work.psm1`로 화면 밖에서 합니다. 로컬처럼 보이는 경로도 끊긴 네트워크 드라이브일 수 있어서 모두 이 길로 갑니다. 탭은 실행 공간 · 스레드 · .NET 작업을 직접 만들지 않습니다(`tests/Test-Core.ps1`이 검사). 데이터 파일은 원래대로 `Get-WtStoreItems` · `Write-WtStore`를 쓰면 저장 모듈이 이 길로 갑니다.
  - `Start-WtWork { param($p) ... } -ArgumentList $p -OnDone { param($w) ... }`: PowerShell 코드를 화면 밖에서 돌리고, 끝나면 화면 스레드에서 `-OnDone`을 한 번 부릅니다(`$w.State` = done · failed · timedout, `$w.Result` · `$w.Error` · `$w.Context`). 기본 세션에는 명령이 없고 PowerShell 문법과 .NET만 됩니다. Get-ChildItem 같은 명령이 필요하면 `-Session Default`, STA 스레드가 필요한 .NET(UI Automation · 클립보드)은 `-Sta`. 탭 모듈의 함수는 `-Functions (Get-Command 함수이름)`으로 넘깁니다.
  - .NET 메서드 하나로 끝나는 일(파일 읽기 · 있는지 보기)은 `Start-WtWork -Call (New-WtCall ([System.IO.File]) ReadAllText $path)`처럼 실행 공간 없이 부릅니다. 가장 빠릅니다. 나머지 매개변수(`-OnDone` · `-TimeoutMs` · `-Key` · `-Context`)는 같고, 결과는 `$w.Result`입니다.
  - `-TimeoutMs`가 지나면 기다리지 않고 `timedout`으로 `-OnDone`을 부르고 작업은 버립니다. `-Key (Get-WtPathKey $path)`로 같은 곳(드라이브 · 공유)을 묶으면, 시간이 지난 작업이 남은 곳은 `Test-WtWorkStuck`이 `$true`입니다. 탭은 새로 묻기 전에 이것을 보고 바로 알립니다(마크다운 그림 · 업무 탭이 이렇게 하고, `Open-WtPath`와 저장 모듈은 스스로 합니다). 남은 작업이 끝나면 `$false`로 돌아옵니다.
  - 결과가 바로 필요하면 `Invoke-WtWork ... -TimeoutMs 5000`(시간 안에 답이 없으면 `TimeoutException`). 화면을 그리기 전에 짧게 기다리려면 `Wait-WtWork $w -Milliseconds 80`. 로컬 경로는 그 안에 끝나서 「불러오는 중」이 깜빡이지 않습니다. `-OnDone`이 화면을 바꾸므로 화면을 다 꾸린 뒤에 기다립니다(문서 · 업무 탭 참고).
  - 파일 · 폴더를 원래 프로그램 · 탐색기로 여는 것은 `Open-WtPath $path`로만 합니다. `-Reveal`은 탐색기에서 골라 보기, `-OpenTypes`는 폴더와 그 확장자만 열고 나머지는 탐색기에서 골라 보기(마크다운 링크), `-NotFound`는 없을 때 알릴 글입니다. 실행 파일을 열기 전에 묻는 것은 부르는 탭이 합니다(문서 탭). 있는지 확인과 셸 열기를 모두 화면 밖에서 하고, 5초 안에 답이 없으면 알립니다(셸에 넘기기 전이면 열지 않고, 넘긴 뒤면 늦게 열릴 수 있다고 알립니다). `Invoke-Item` · `explorer.exe`를 직접 부르지 않습니다(`tests/Test-Core.ps1`이 검사).
  - 되돌릴 수 없는 일(셸 열기 · 프로세스 만들기)을 화면 밖에서 할 때는 그 직전에 잠금 안에서 취소를 보고 `$WtCancel.Committed`를 둡니다. 쓰는 법은 `core/Work.psm1`의 `Start-WtWork` 도움말에 있습니다. 화면이 넘겨받아야 하는 결과(프로세스)는 만든 쪽이 넘길 때까지 들고 있다가, 넘기기 전에 취소 · 종료되면 만든 쪽이 정리합니다(업무 탭 `Start-WtFlowChild` · `Stop-WtFlowStarting`).
  - 끝낼 때(`Register-WtAddon -OnExit { ... }`)는 남은 작업을 `Stop-WtWork $w`로 버리고 기다리지 않습니다. 버린 작업의 `-OnDone`은 불리지 않습니다. 탭이 자기 상태(진행 중 표시 등)를 함께 정리하려고 직접 부르는 것이고, 남은 것은 셸이 버립니다. 실행 공간의 Stop · Close · Dispose와 시간을 정하지 않은 기다림은 응답 없는 작업이 끝나기를 기다려 앱을 멈추게 하므로 쓰지 않습니다. 셸은 탭의 `-OnExit` 뒤에 남은 작업을 모두 버립니다(`Stop-WtAllWork`).
  - PowerShell은 프로세스가 끝날 때 열린 실행 공간을 모두 닫으며 그 안의 작업이 끝나기를 기다립니다. 응답 없는 OS 요청은 돌아오지 않으므로, 진입 스크립트(`Start-WorkTool.ps1`, 묶음 파일 `WorkTool-WPF.ps1`)는 앱을 끝낸 뒤 `Exit-WtOwnProcess`로 앱 전용 프로세스를 끝냅니다. `-File`로 이 파일을 띄운 프로세스만 끝냅니다. 개인 PC 실행 파일 · `pwsh -STA -File .\WorkTool-WPF.ps1` · 쓰던 창에서 `.\WorkTool-WPF.ps1`(아래 「성능 설정」의 한 번 다시 실행)은 모두 `-File`로 띄운 새 프로세스에서 앱이 돌아서 끝납니다. `DOTNET_TieredCompilation=0`을 미리 둔 창에서 바로 띄우면 그 창을 끄지 않으려고 끝내지 않습니다(이때는 남은 작업이 끝날 때까지 창을 닫을 때 기다릴 수 있습니다). `tests/Test-Core.ps1` · `tests/Test-Launcher.ps1`이 끝나지 않는 작업을 남긴 채 프로세스가 끝나는지 검사합니다.
  - 탭 검사에서 응답 없는 공유 폴더는 `tests/TestKit.ps1`의 `New-WtTestGate` · `$wtTestHang`으로 흉내 냅니다. 외부 프로그램 · 관리자 권한 · 실제 서버 없이, 문을 열 때까지 돌아오지 않는 작업을 만듭니다. `$gate = New-WtTestGate`로 문을 만들고, 탭의 화면 밖 코드(`$script:worker` 같은 바꿔 끼울 수 있는 스크립트 블록)를 `$wtTestHang`으로 바꾼 뒤 `$gate.Entered.WaitOne()`으로 작업이 들어왔는지 봅니다. 끝나면 `Remove-WtTestGate $gate`로 문을 열고 남은 작업을 치웁니다. 예: `addons/docs/Test-Docs.ps1`.
    - 바꿔 끼우는 곳은 OS에 닿는 한 곳만으로 좁힙니다. 그 앞에 기다림만 끼우고 실제 코드는 그대로 돌려서, 상태 바꾸기 · 소유권 처리까지 검사에 들어가게 합니다. 예: 저장은 `Write-WtDataFile` 앞(`tests/Test-Reliability.ps1`), 셸 열기는 `Get-WtPathAttributes` · `Invoke-WtShellStart`(`tests/Test-Core.ps1`), 업무 실행은 `Start-WtFlowChild` 앞(`addons/workflows/Test-Workflows.ps1`).

## 마크다운 보기

메모 본문을 보여 주는 공통 부품입니다. `.md` 파일을 앱 안에서 보여 줄 화면이 생기면 같은 부품을 씁니다. 특정 화면을 위한 코드는 부품에 넣지 않고, 화면마다 다른 것은 매개변수로 넘깁니다.

```powershell
$view = New-WtMarkdownView -Scroll -BaseDir 'D:\문서' -OnLink {
    param($link, $st)   # @{ Kind = 'url' | 'file' | 'wiki' | 'tag'; Target; Text }, 보기 상태(Tag)
    if ($link.Kind -eq 'wiki') { Open-MyDoc $link.Target; return $true }   # 처리했으면 $true
    $false                                                                # 아니면 기본 동작
} -OnTask { param($line, $el) Switch-MyTask $line }                       # 할 일 체크 표시를 누를 때 (원문 줄 번호, 누른 요소)
Set-WtMarkdownText $view $text
```

- `-Scroll`: 남는 높이를 채우고 스스로 스크롤합니다. 빼면 글 높이만큼 커집니다(바깥이 스크롤하는 화면).
- `-BaseDir`: 상대 경로 그림 · 파일 링크의 기준 폴더. 메모처럼 파일이 아닌 글은 비워 둡니다.
- `-OnLink`: 링크 · `[[위키 링크]]` · `#태그`를 눌렀을 때. 이게 있으면 태그도 누를 수 있게 그립니다. 처리하지 않은 링크의 기본 동작은 아래와 같습니다.
  - 웹 주소: `http` · `https` · `mailto`만 기본 브라우저 · 메일 프로그램으로 엽니다.
  - 파일: 폴더는 탐색기로, 문서 · 그림은 기본 프로그램으로 엽니다. 실행 파일 · 스크립트는 열지 않고 탐색기에서 그 파일을 보여 줍니다.
    - 있는지 · 폴더인지 확인과 열기는 화면 밖에서 합니다(`Open-WtPath`, 위 「탭(애드온) 더하기 · 빼기」). 확인하는 동안 커서가 AppStarting(화살표 + 모래시계)이 되고, 앱은 계속 쓸 수 있습니다. 같은 링크를 또 눌러도 겹쳐 확인하지 않습니다.
    - 5초 안에 답이 없으면 기다리지 않고 알립니다. 확인 중이었으면 「경로가 응답하지 않습니다」를 알리고 늦게 답이 와도 열지 않습니다. 이미 Windows에 열기를 넘긴 뒤였으면 늦게 열릴 수 있다고 알립니다(위 「데이터」). 같은 공유(`\\서버\공유` · 드라이브)에 답 없는 확인이 남아 있으면 새로 묻지 않고 바로 같은 문구를 알립니다.
  - 같은 문서 안 제목(`[[#제목]]`, `(#제목)`) · 각주: 그 자리로 스크롤합니다.
- 파일 · 폴더 링크는 링크 글 앞에 문서 · 폴더 아이콘을 붙이고, 툴팁에 Windows 모양 전체 경로를 보입니다. 메모 편집기가 쓰는 `[이름](<C:/a b/c.txt>)` · `[이름](<//서버/공유/x>)`, 역슬래시 경로, `file:` 주소 모두 파일 링크입니다.
  - 폴더인지는 디스크를 보지 않고 이름으로 추측합니다(그리는 중에 네트워크 경로를 건드리지 않게). 끝이 `/` · `\`, 드라이브 루트, UNC 공유 루트, 마지막 이름에 확장자가 없으면 폴더 아이콘입니다.
- 그림: 로컬 · 공유 경로의 그림 파일은 화면 밖에서 읽고, 읽은 내용으로 그립니다. 그리기 끝에 0.15초까지 기다리므로 로컬 그림은 처음부터 제자리에 보입니다. 늦는 그림은 그 자리에 그림 아이콘과 이름을 두었다가 읽히면 바꿉니다(10초 안에 답이 없으면 「그림 경로가 응답하지 않습니다」). 없는 그림 · 못 읽은 그림도 아이콘과 이름만 보이고, 마우스를 올리면 이유가 보입니다. 한 번에 6개까지 읽고, 64MB가 넘는 그림 파일은 그리지 않습니다.
- `-OnTask { param($line) ... }`: 할 일 체크 표시를 누를 수 있게 그리고(손 모양 커서, 툴팁 「완료 표시 / 해제」), 누르면 그 항목의 원문 줄 번호(1부터)로 부릅니다. 빼면 체크 표시는 누를 수 없습니다(읽기 전용 보기).
- `-StrictLineBreaks`: 줄바꿈 한 번을 이어 붙입니다(표준 마크다운). 기본은 Obsidian처럼 줄을 바꿉니다.
- 더 붙이기: 코드 블록을 언어별로 따로 그리려면 `Register-WtMarkdownCodeRenderer`(Mermaid가 이렇게 붙어 있음), 콜아웃 종류는 `Register-WtMarkdownCallout`, 코드 색칠 언어는 `Register-WtCodeLanguage`.
- `Get-WtMarkdownSnippet`: 목록 한 줄 요약용으로 마크다운 기호를 뗀 글. `Get-WtMarkdownHeadings`: 제목 목록(목차용).
- 블록 단위 그리기(글을 고치면서 블록 하나씩 바꿔 그리는 화면용, 메모 편집기가 씀): `Get-WtMarkdownUnits $text`가 글을 블록(단위)으로 나눠 줄 범위 · 종류를 돌려주고, `New-WtMarkdownUnitSection $view $unit`이 단위 하나를 Section 하나로 그립니다. 목록은 항목마다, 안쪽 목록은 깊이를 붙여 따로 나눕니다. 그리면 보이지 않는 줄(링크 정의 · 주석)도 단위가 되어 원문을 흐리게 보여 줍니다. 자세한 약속은 `Markdown.psm1`의 함수 주석에 있습니다.
- `-OnLink`의 둘째 값은 보기 상태, `-OnTask`의 둘째 값은 누른 요소입니다. 보기를 여럿 두거나 그린 블록을 다시 쓰는 화면이 어디서 눌렸는지 찾을 때 씁니다. 첫째 값만 받아도 됩니다.

**되는 것**

## 성능 설정과 측정

- 앱은 `DOTNET_TieredCompilation=0`으로 실행합니다. .NET이 뒤에서 코드를 다시 컴파일하는 동안 화면이 굼떠지는 것을 줄이는 성능 설정입니다([설명](https://learn.microsoft.com/en-us/dotnet/core/runtime-config/compilation#tiered-compilation)). 이 앱의 프로세스에만 적용되고, 실행 정책 · 보안 설정 · 레지스트리 · 사용자 환경 변수는 바꾸지 않습니다.
  - 개인 PC 실행 파일(`Start-WorkTool.cmd` · `start-dev.cmd`)은 GUI 프로세스에만 이 값을 넘깁니다.
  - 업무 PC에서 `.\WorkTool-WPF.ps1`로 켜면 같은 콘솔에서 이 설정으로 한 번 다시 실행합니다. 그만큼 시작이 조금 늦어집니다.
- 탭에 다시 들어올 때는 데이터나 설정이 바뀐 화면만 다시 만듭니다. 문서 · 활성 작업 · 업무 스크립트 목록은 들어올 때마다 다시 모읍니다.
- 화면은 기본으로 **소프트웨어 렌더링**(`RenderOptions.ProcessRenderMode = SoftwareOnly`)으로 그립니다.
  - 개발 PC에서 GPU 렌더링으로 띄우면, 창이 앞에 있거나 탭 위에 마우스만 올려도 PC 전체가 버벅였습니다. 소프트웨어 렌더링에서는 그러지 않았습니다(2026-10-25).
  - WorkTool은 화면이 단순해서 두 방식의 CPU 사용량 · 탭 여는 시간 차이가 측정 오차 수준이었습니다.
  - 이 앱의 프로세스에만 적용됩니다. 레지스트리 · 시스템 설정은 바꾸지 않습니다.
- 미리 만들기는 기본으로 끕니다. 낮은 Dispatcher 우선순위도 화면 하나를 만드는 중에는 입력을 선점 처리하지 못하기 때문입니다. 이미 연 화면의 재사용은 유지합니다.
- 진단할 때만 다음 프로세스 환경 변수를 사용합니다. 정확히 `1`인 값만 켬으로 처리합니다. 실행 정책 · 레지스트리 · 저장된 사용자 설정은 바꾸지 않습니다. 실행 후 부모 콘솔의 환경 변수는 호출자가 `try/finally`로 원복해야 합니다.
  - `WORKTOOL_WARMUP=1`: 세션당 한 번 미리 만들기를 예약합니다. 활성 · 모달 · 최소화 · 숨김 · 종료 중에는 기다립니다. 한 단계가 시작된 뒤에는 여전히 UI를 점유하므로 일반 실행에 권하지 않습니다.
  - `WORKTOOL_FORCE_OPAQUE=1`: 그 세션의 창만 `AllowsTransparency=False`, `Opacity=1`로 고정합니다.
  - `WORKTOOL_HARDWARE_RENDER=1`: 소프트웨어 렌더링 대신 GPU 렌더링으로 띄웁니다. 그래픽 경로를 비교할 때만 씁니다.
- `tests/Measure-WtPerformance.ps1`은 창 없이 임시 데이터로 화면 만드는 비용을 짧게 확인합니다. 전체 검사에는 들어가지 않고, 실행 전에 사용자에게 범위를 알리고 허락을 받습니다(`AGENTS.md`).

  ```powershell
  pwsh -NoProfile -STA -File ./apps/WorkTool/wpf/tests/Measure-WtPerformance.ps1 -OutputPath ./.work/perf-light
  ```

## 이 창에서 쓰지 않는 것

- 창 투명도를 100%보다 낮게 고르면 테두리 없는 투명 창(AllowsTransparency)으로 띄웁니다. 투명 창은 ClearType을 쓸 수 없어 글자가 흐려지므로, 100%면 보통 창으로 띄웁니다. 투명 창 여부는 창을 띄울 때만 정할 수 있어서, 100%와 그 아래를 오가면 다시 시작해야 적용됩니다(설정 화면에 안내가 뜹니다). 투명 창일 수 있으므로 이 창 안에는 WinForms 컨트롤(WindowsFormsHost)이나 WebBrowser를 넣지 않습니다(그려지지 않음). 마크다운은 PowerShell 7에 들어 있는 Markdig로 읽어 WPF 문서(FlowDocument)로 그리고, Mermaid도 직접 배치해서 WPF 도형으로 그립니다.
