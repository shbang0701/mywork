# WorkTool 새 버전 (WPF) — 메모 · 문서 · 활성 작업 · 업무

지금 쓰는 WorkTool(WinForms, `apps/WorkTool/`)을 옮겨 갈 새 버전입니다.
계획과 결정 사항은 이슈 #8 「WorkTool 개편 계획 · 결정할 것」, 화면 기준은 `apps/WorkTool/design/README.md`에 있습니다.

## 1단계에 들어 있는 것

- 창 틀: 제목 줄을 직접 그린 창(최소화 · 최대화 · 닫기), 창 투명도, F11 전체 화면
- 왼쪽 메뉴: 애드온(탭) 목록으로 자동으로 만든다. 접기 · 펼치기(Ctrl+B), 아래에 설정 · 도움말
- 테마: 파스텔 7색(하늘 · 분홍 · 연두 · 노랑 · 보라 · 회색 · 검정), 창 투명도 60~100%, 글자 크기 3단계. 바꾸면 바로 반영
- 설정 화면: 테마, 메뉴에서 탭 끄기, 데이터 위치, 예전 데이터 다시 가져오기
- 예전 데이터 가져오기: 처음 실행하면 예전 WorkTool의 `data` 폴더에서 메모 · 일정 · 근태를 읽어 와서 보여 준다
- 탭: 홈(다른 탭의 카드 모음) · 일정 · 근태(**보기 전용**) · 메모 · 문서 · 활성 작업 · 업무
- 활성 작업: 실행 중인 앱 창과 Chrome·Edge·웨일 탭 제목을 프로그램별 표로 봅니다. 선택 닫기, 수동·자동 새로 고침을 지원합니다. 자세한 사용법은 아래 「활성 작업」에 있습니다.
- 업무: 스크립트 폴더의 PowerShell 스크립트를 폼으로 실행합니다. param이 입력 칸이 되고, 자주 쓰는 값은 업무로 저장합니다. 자세한 사용법은 아래 「업무」에 있습니다.
- 문서: [폴더 추가]로 고른 폴더(공유 폴더도 됨)를 왼쪽 트리로, 오른쪽에 파일 목록(이름 · 종류 · 고친 날짜 · 크기, 이름으로 거르기). 두 번 클릭 · Enter · [열기]는 원래 프로그램으로 열고, 폴더면 들어간다. 실행 파일(.exe · .ps1 · .bat …)은 한 번 묻는다. [폴더에서 보기] · [경로 복사] · [즐겨찾기] (홈 카드에도 보임). 폴더 목록 · 즐겨찾기는 데이터 폴더의 `settings.json`에만 저장한다(저장소에 올라가지 않음). 마지막으로 본 폴더를 열 수 없으면 첫 폴더를 연다. 파일 내용은 읽거나 옮기지 않는다
- 메모: 편집 | 미리보기(마크다운), [새 메모] (Ctrl+N), 자동 저장(입력을 멈추고 0.8초 뒤 · 다른 메모로 옮길 때 · 끌 때, Ctrl+S는 바로), 삭제 후 10초 동안 실행 취소. 제목을 비우면 저장 시각이 제목. 본문의 `#태그`는 `tags`에 모은다. Ctrl+E로 편집 / 미리보기
- 마크다운 보기: 문법 예시는 도움말 → 마크다운. 자세한 것은 아래 「마크다운 보기」
- 창의 X는 앱을 끝낸다. 설정 → 닫기 버튼에서 「트레이로 숨기기」를 고르면 트레이에 남고, 끄려면 트레이 아이콘 우클릭 → 종료
- 아이콘: 강조색 둥근 사각형에 W. 제목 줄 왼쪽 · 작업 표시줄 · 트레이에 같은 모양으로 보이고, 테마 색을 바꾸면 같이 바뀐다

일정 · 근태 편집, 알람, 지금 출근, 메모별 잠금은 2단계에서 옮깁니다. 그때까지는 예전 WorkTool을 계속 쓰세요.
새 버전에서 쓴 메모는 예전 WorkTool에 보이지 않고, 설정의 「다시 가져오기」를 누르면 예전 데이터로 덮어씁니다(직전 파일은 `.bak`).

## 개인 PC에서 실행하기

**저장소를 받아 둔 PC**(`git clone`)는 zip이 필요 없습니다. `apps/WorkTool/wpf/start-dev.cmd`를 더블클릭하면 이 폴더의 원본을 바로 띄우므로, 고친 내용이 바로 보입니다. 바탕 화면에 바로 가기를 만들어 두면 편합니다.
- 데이터는 zip으로 띄울 때와 같은 곳(문서\WorkTool)을 써서 메모 · 설정이 그대로 보입니다. 둘을 함께 띄우면 나중 것은 중복 실행으로 막힙니다.
- 작업 중인 브랜치를 미리 보려면 그 브랜치로 바꾼 뒤 띄웁니다.

**저장소가 없는 PC**는 저장소 맨 위 `worktool.zip`을 받아 우클릭 → 속성 → 「차단 해제」 체크 → 압축을 풀고 `Start-WorkTool.cmd`를 더블클릭합니다. 실행 보조 창은 바로 닫히고 GUI만 남습니다. `.cmd`의 초기 창이 잠깐 보일 수는 있습니다.
- 압축 안의 `WorkTool-WPF.ps1`, `Start-WorkTool.cmd`, `Start-WorkTool-Launcher.ps1` 세 파일을 같은 폴더에 둡니다. 시작 검사에 실패하면 실행 창에 오류를 표시합니다. 실행 정책은 바꾸지 않습니다.
- 작은 W 배지 대신 창의 전체 아이콘을 적용합니다. Windows 작업 표시줄의 기존 고정 아이콘·PowerShell 묶음은 시스템 설정에 따라 PowerShell 모양으로 남을 수 있습니다.
zip은 `build/Build-Bundle.ps1`이 묶음 파일과 같이 만듭니다.

## 업무 PC에서 실행하기

1. `apps/WorkTool/dist/WorkTool-WPF.ps1`을 복사해서, 예전 WorkTool 폴더(예전 `data` 폴더가 있는 곳)에 같은 이름으로 저장합니다.
2. `pwsh`에서 `.\WorkTool-WPF.ps1`로 실행합니다.
3. 확인할 것
   - 창이 뜨고, 왼쪽 메뉴에 홈 · 일정 · 근태 · 메모가 보이는지
   - 홈 · 일정 · 근태 · 메모에 예전 데이터가 보이는지
   - 설정에서 색 · 글자 크기를 바꾸면 바로 바뀌는지. 투명도는 100%와 그 아래를 오가면 다시 시작한 뒤 바뀌는지(설정 화면에 안내가 뜸)
   - 최대화 · F11 · Ctrl+B · X로 끝내기 (설정에서 트레이로 숨기기를 고르면 트레이에서 종료)
   - 도움말 → 마크다운: 코드 블록 [복사], 접는 콜아웃 펼치기, 다이어그램, 보기 | 원문 바꾸기
   - 메모: 본문이 마크다운으로 보이는지, `[[다른 메모 제목]]` · `#태그`를 누르면 그 메모 · 검색으로 가는지
   - 메모 쓰기: 새 메모 → 제목 · 본문 입력 → 「자동 저장됨」 표시, 앱을 껐다 켜도 남는지, 삭제 → 실행 취소
   - 문서: 폴더 추가(공유 폴더 포함) → 트리 펼치기 · 파일 두 번 클릭으로 열기(DRM 문서 포함) · 즐겨찾기 → 홈 카드에서 바로 열기
   - 활성 작업: 표의 창·탭 확인 → 새로 고침 우클릭 → 자동 → 1분 적용 → 목록 갱신. 닫기 검사는 먼저 저장한 테스트 문서나 빈 탭으로 확인
   - 업무: [폴더 추가]로 스크립트 폴더(예: `문서\WorkTool\scripts`) → `Watch-MultiPing` 고르기 → 콘솔 창에서 [실행] → 그 창에서 Q로 끝내고 요약 CSV 확인. 앱 안 실행은 `Rounds` 칸에 3을 넣고 [실행] → 출력 · 「성공」 확인

오류가 나면 창에 뜬 문구(또는 콘솔의 빨간 글씨)를 그대로 알려 주세요.

- "STA 모드에서 실행해야 합니다"가 나오면 `pwsh -STA -File .\WorkTool-WPF.ps1`로 실행합니다.
- 예전 데이터를 못 찾으면 설정 → 데이터 → 「위치 고르기」에서 예전 `data` 폴더를 고릅니다.

## 활성 작업

앱 창과 Chrome·Edge·웨일 탭 제목을 **프로그램별 표**로 보여 줍니다. 실행하지 않은 작업 표시줄 고정 아이콘, 백그라운드 프로세스, WorkTool 자체 창은 대상이 아닙니다. 관리자 권한 앱이나 보안 프로그램이 정보를 제한하는 창은 읽거나 닫지 못할 수 있습니다.

WorkTool을 띄운 터미널(Windows Terminal · PowerShell 창 · VS Code 등)은 표에 `WorkTool 실행 중`으로 보이지만 닫지 않습니다. 그 창을 닫으면 WorkTool도 함께 꺼지기 때문입니다.

**찾기와 선택**
- 이름 검색(Ctrl+F), 프로그램 필터, 열 머리글 정렬을 지원합니다. 프로그램 묶음을 접고 펼칠 수 있습니다.
- 행의 체크박스로 닫을 대상을 고릅니다. 그룹 체크는 현재 검색·필터에 포함된 항목만 대상으로 합니다. 닫기를 지원하지 않는 행은 체크할 수 없습니다.
- 같은 창 안의 동일 제목 탭은 `(탭 2)`처럼 순서를 덧붙입니다. 새로 고침할 때는 제목 대신 창·탭 식별자로 체크와 접기 상태를 유지합니다. 검색·필터를 바꾸면 체크를 해제합니다.

**수동·자동 새로 고침**
1. [새로 고침]을 왼쪽 클릭하거나 F5를 누르면 한 번 수집합니다.
2. 버튼을 우클릭하면 [수동] · [자동…]이 나옵니다. 키보드는 버튼에 포커스를 둔 뒤 Shift+F10입니다.
3. [자동…]을 고르면 분 입력 대화상자가 열립니다. 처음 제안값은 **5분**, 범위는 **1~1,440분의 정수**입니다. [적용]을 눌러야 모드와 간격이 바뀝니다. 취소·Esc·창 닫기는 기존 설정을 유지합니다.
4. [수동]을 고르면 자동 갱신을 멈추고 마지막 간격은 기억합니다. 현재 모드는 버튼 옆에 표시합니다.

기본 모드는 수동입니다. 모드·간격은 로컬 `settings.json`의 `tasks.refresh`에 저장해 재실행해도 유지합니다. 자동 모드에서도 버튼 클릭과 F5는 사용할 수 있습니다. 활성 작업 탭이 보이고 앱 창이 최소화·트레이 숨김 상태가 아닐 때만 자동 수집합니다. 설정·닫기 확인창이 열려 있거나 이미 수집/닫기를 처리 중이면 새 작업을 겹쳐 시작하지 않습니다. 자동 간격은 수집이 끝난 시점부터 셉니다.

**선택 닫기**
- [선택 닫기]에서 대상 목록을 확인한 뒤 [닫기]를 누릅니다. 창·탭의 식별자와 제목이 바뀌었으면 건너뜁니다.
- 원래 프로그램의 일반 닫기 기능을 요청합니다. 저장 확인·페이지 이탈 확인은 원래 프로그램에서 직접 처리하세요. 강제 종료, 자동 저장, 자동 「저장 안 함」 선택은 하지 않습니다.
- 결과는 닫힘 · 이미 없음 · 확인 필요 · 실패 · 취소로 표시합니다. 결과에 마우스를 올리면 항목별 사유를 볼 수 있습니다. 닫힘을 확인하지 못하면 완료로 표시하지 않습니다.
- [취소]는 다음 항목부터 중단합니다. 이미 보낸 닫기 요청을 되돌리지는 않습니다. 응답이 느린 프로그램의 현재 요청은 반환될 때까지 기다릴 수 있습니다.

**지원 범위와 검사**
- PowerShell과 Windows 기본 .NET UI Automation만 씁니다. 추가 앱·모듈·확장 프로그램·디버깅 포트는 필요 없습니다. 브라우저 프로필·방문 기록·페이지 본문을 읽지 않고, 수집한 제목을 파일에 저장하지 않습니다.
- 수집은 창을 복원하거나 탭을 전환하지 않습니다. 브라우저가 정보를 내주지 않으면 `탭 확인 불가` 또는 `일부 탭 확인 불가`로 표시합니다. 브라우저 창 전체 닫기로 대신하지 않습니다.
- 웨일은 Chrome과 같은 방식으로 탭을 읽습니다. 실제 웨일에서는 아직 확인하지 않았으며, 탭을 못 읽으면 `탭 확인 불가`로 둡니다.
- 브라우저는 UI Automation으로 탭을 읽으면 접근성 기능을 켜서 메모리를 조금 더 쓸 수 있습니다. 보안 프로그램이 다른 앱 화면을 읽는 동작으로 볼 수도 있으니, 자동 새로 고침은 업무 PC에서 한 번 확인한 뒤 켜세요.
- `addons/active-tasks/Test-ActiveTasks.ps1`은 임시 데이터와 전용 테스트 창만 씁니다. 코어 검사가 찾아서 돌리며, Windows STA에서는 실제 그룹 체크·모달·타이머 경로와 UIA 닫기까지 검사합니다.
- 설치된 브라우저를 추가로 검사하려면 해당 실행 파일을 `-BrowserPath`로 명시합니다. 새 임시 프로필의 가짜 페이지 두 개만 열고 기존 프로필을 사용하지 않습니다. 브라우저 첫 시작 정책으로 테스트 프로필 실행이 막히면 제한을 우회하지 않습니다.
- 업무 PC의 DRM 앱과 보안 정책은 환경마다 다릅니다. 해당 환경에서도 정상 동작한다고 미리 보장하지 않습니다.

## 업무

스크립트 폴더의 PowerShell 스크립트를 폼으로 실행합니다. 업무 기능은 앱이 아니라 스크립트로 더하므로, 새 기능은 스크립트 파일 하나를 폴더에 넣으면 됩니다. 설계와 스크립트 약속은 [업무 탭 설계](../../../docs/plans/workflows-design.md), 화면은 [디자인 README의 업무](../design/README.md#업무-실제-화면)에 있습니다.

1. [폴더 추가]로 스크립트 폴더를 고릅니다. 하위 폴더 3단계까지 `.ps1`을 찾고, 이름이 `_`로 시작하는 파일은 뺍니다. 업무 PC에서는 예를 들어 `문서\WorkTool\scripts`에 필요한 스크립트만 복사해 둡니다.
2. 왼쪽에서 스크립트를 고르면 param이 입력 칸이 됩니다. 칸 설명은 `.PARAMETER`, 없으면 param 줄 끝 주석입니다. 비운 칸은 넘기지 않아서 스크립트 기본값(설정 블록 값)을 씁니다.
3. [실행]은 고른 실행 방식으로 돌립니다.
   - 앱 안에서: 창 없이 돌리고 출력을 아래 칸에 보여 줍니다. [취소]는 자식 프로세스까지 끝냅니다. 이때 스크립트의 마무리 처리(`finally`)는 돌지 않을 수 있습니다.
   - 콘솔 창에서: 보이는 PowerShell 창을 띄웁니다. 끝나도 창이 남고, 사용자가 닫습니다. 도움말 `.NOTES`에 `WorkTool: 콘솔`이 있는 스크립트(`Watch-MultiPing.ps1` 등)는 이 방식이 기본입니다.
   - [미리보기]는 `-WhatIf`를 붙여 할 일만 보여 줍니다(`SupportsShouldProcess` 스크립트만).
4. 자주 쓰는 값과 실행 방식은 [업무로 저장]합니다. 저장한 업무는 왼쪽 맨 위와 홈 카드에 보입니다. [업무 삭제]는 바로 지우고 [실행 취소]로 되돌립니다.

- 실행 기록은 모든 스크립트를 합쳐 최근 100건을 둡니다. 오른쪽 「최근 실행」에서 기록을 누르면 그때 출력의 마지막 40줄을 출력 칸에 다시 보여 줍니다. 콘솔 창 실행은 출력을 남기지 않습니다.
- 앱을 끄면 앱 안 실행도 멈춥니다(창 없는 프로세스를 남기지 않음). 콘솔 창은 따로 도는 창이라 그대로 둡니다.
- 실행 정책은 바꾸지 않습니다. 정책에 막히면 그 오류가 출력에 보이고 결과는 「실패」입니다. 스크립트는 실행하지 않고 구문만 읽어서 폼을 만듭니다.
- 비밀 값(이름에 Password · Token 등이 들어간 param)과 폼에 넣을 수 없는 종류(`[string[]]` 등)는 칸이 생기지 않습니다. 그런 값이 필수이면 콘솔 창에서만 실행하고, 창에서 PowerShell이 직접 묻습니다.
- F5: 스크립트 목록 새로 고침. 다른 탭에 다녀와도 고치던 칸 값은 그대로 둡니다.
- 창이 좁으면(메뉴를 펼친 기본 창 크기 포함) 오른쪽 설명은 접혀 있습니다. [설명 펼치기]를 누르면 가운데 위에 겹쳐 뜨고, [접기]나 Esc로 닫습니다.

## 데이터

- 업데이트할 때는 기존 창과 트레이의 WorkTool을 모두 종료한 뒤 파일을 바꾸세요. 같은 데이터 폴더를 쓰는 새 실행본끼리는 중복 실행을 막습니다. `.worktool.lock` 파일이 남아도 정상이며, 앱이 끝나면 잠금은 풀립니다.
- 메모를 저장하지 못하면 메모 화면을 떠나거나 끝낼 때 [다시 시도] · [이동] (끝낼 때는 [끝내기]) · [취소]를 묻습니다. [이동]해도 고친 내용은 메모 화면에 남고, [끝내기]를 고르면 저장하지 못한 내용은 사라집니다. 파일 잠금·폴더 쓰기 권한 문제를 해결한 뒤 Ctrl+S로 다시 저장하세요. 강제 종료·전원 차단 때 아직 저장하지 않은 글까지 복구하는 기능은 아닙니다.
- 문서·메모 목록은 보이는 행만 만들고, 문서 폴더·즐겨찾기 조회는 화면과 별도로 처리합니다. 조회 중에도 다른 탭을 쓸 수 있으며 [취소]로 결과 반영을 취소할 수 있습니다. 응답 없는 공유 폴더의 진행 중인 OS 요청은 바로 멈추지 않을 수 있지만, 취소했거나 다른 폴더로 옮긴 조회는 기다리지 않고 새 조회를 바로 시작합니다.
- 새 버전 데이터는 앱 폴더 밖, **문서\WorkTool**에 저장합니다. 앱 파일을 새로 덮어써도 데이터는 그대로입니다.
  - 위치를 바꾸려면 앱 파일 옆에 `datapath.txt`를 만들고 첫 줄에 경로를 적습니다.
- 파일: `memo.json` · `schedule.json` · `attendance.json` · `workflows.json`(저장한 업무) · `workflow-runs.json`(실행 기록) · `settings.json`. 저장할 때마다 직전 파일을 `.bak`으로 하나 남깁니다.
- 각 파일에 `schema` 번호가 있습니다. 형식이 바뀌면 읽을 때 자동으로 변환하고, 변환 전 원본은 `.schema<번호>.bak`으로 남깁니다.
- `settings.json`에는 기본값과 다른 설정만 저장합니다.
- 예전 WorkTool의 CSV는 읽기만 하고 바꾸지 않습니다.

## 탭(애드온) 더하기 · 빼기

탭 하나를 더하거나 빼는 일은 `addons/<이름>/` 폴더 하나로 끝납니다. 코어 · 다른 탭 · 검사 목록 · 묶음 만들기는 고치지 않습니다.

- **더하기**: `addons/<이름>/<이름>.psm1`을 만들고 맨 아래에서 `Register-WtAddon`을 부릅니다. 메뉴 · 홈 카드 · 도움말 · 예전 데이터 가져오기가 저절로 연결됩니다.

  ```powershell
  Register-WtAddon -Id 'files' -Title '문서' -Icon 0xE8B7 -Order 50 `
      -NewView { New-WtFilesView } `
      -Refresh { param($view) Update-WtFilesView } `
      -HomeCard { New-WtFilesHomeCard } `
      -Help '문서는 고른 폴더의 파일을 보고 원래 프로그램으로 엽니다.' `
      -Shortcuts @(@('F5', '새로 고침'), @('Ctrl + F', '이름으로 거르기'))
  ```
  - `-Help`는 도움말 「이 버전」 문단, `-Shortcuts`는 「단축키」 줄이 됩니다. 키와 설명이 다른 탭과 같으면 `문서 · 활성 작업: 새로 고침`처럼 한 줄로 묶입니다. 키 처리 자체는 탭 화면이 합니다.
  - 도움말에 카드를 따로 두려면 `-HelpCard { ... }`로 카드 요소를 돌려줍니다 (메모의 마크다운 예시).
  - 처음 누를 때도 빨리 뜨게 하려면 `-WarmUp`을 줍니다. 앱을 켠 뒤 한가할 때 셸이 화면을 미리 만들어 둡니다.
    - `-WarmUp Full`: `-NewView`와 `-Refresh`까지 미리 부릅니다. `-Refresh`가 그 탭의 데이터 파일만 읽을 때 씁니다(일정 · 근태 · 메모).
    - `-WarmUp View`: `-NewView`만 미리 부릅니다. `-Refresh`가 폴더 조회 · 다른 창 읽기처럼 느리거나 앱 밖에 닿을 때 씁니다(문서 · 활성 작업 · 업무).
    - 주지 않으면 처음 누를 때 만듭니다. 미리 만들 때 `-NewView`는 화면 요소만 만들고, 조회 · 타이머 시작은 `-Refresh`나 화면이 보일 때로 미룹니다.
  - 검사는 같은 폴더의 `Test-<이름>.ps1`에 둡니다. 맨 위에서 `tests/TestKit.ps1`을 점 소싱하고 `Import-WtTestCore` → 자기 모듈 불러오기 → `New-WtTestData`로 임시 데이터를 만듭니다. `tests/Test-Core.ps1`이 찾아서 돌리고, 묶음 파일에는 들어가지 않습니다.
- **빼기**: 그 폴더를 지웁니다. 그 탭의 도움말 · 단축키 · 검사도 같이 빠지고, 다른 탭과 데이터는 그대로입니다. 잠깐 숨기기만 하려면 설정 → 메뉴에서 끕니다.
- 코어 코드와 코어 검사에는 특정 탭의 이름 · 설명 · 단축키를 쓰지 않습니다. 탭이 필요한 코어 검사는 가짜 탭을 등록해서 합니다.
  - 예외 1: 모양(스타일)은 `core/Ui.psm1`에만 둡니다. 탭에 새 모양이 필요하면 그곳에 쓰임새 이름으로 더합니다.
  - 예외 2: 예전 WorkTool(WinForms) 데이터 폴더를 알아보는 CSV 이름(`memo.csv` 등)입니다. 이미 정해진 예전 형식이라서입니다.
- 화면은 `core/Ui.psm1`의 `New-Wt*` 함수와 스타일 이름만 써서 만듭니다. 색 값이나 글꼴 이름을 직접 쓰지 않습니다.
- 저장은 `Get-WtStoreItems` · `Write-WtStore`만 씁니다. 형식을 바꿀 때는 `-Schema`를 올리고 `-Migrate`로 변환을 줍니다.
- 이벤트 처리기 안에서는 `$script:` 변수와 보낸 요소(`$s`)의 `Tag`만 씁니다. 처리기는 나중에 불리므로, 만든 함수의 지역 변수는 보이지 않습니다.
- 오래 걸리는 일(폴더 조회 · 출력 읽기 등)은 따로 만든 실행 공간에서 돌리고, 결과는 `DispatcherTimer`로 가져옵니다(문서 · 업무 탭 참고). 실행 공간은 `ThreadOptions = 'UseNewThread'`로 만들고 끝나면 `Dispose()`합니다. `ReuseThread`는 버리기 전까지 스레드가 남아, 창을 닫아도 앱 프로세스가 끝나지 않습니다. `tests/Test-Core.ps1`이 이것을 검사합니다.

## 마크다운 보기

메모 본문을 보여 주는 공통 부품입니다. `.md` 파일을 앱 안에서 보여 줄 화면이 생기면 같은 부품을 씁니다. 특정 화면을 위한 코드는 부품에 넣지 않고, 화면마다 다른 것은 매개변수로 넘깁니다.

```powershell
$view = New-WtMarkdownView -Scroll -BaseDir 'D:\문서' -OnLink {
    param($link)   # @{ Kind = 'url' | 'file' | 'wiki' | 'tag'; Target; Text }
    if ($link.Kind -eq 'wiki') { Open-MyDoc $link.Target; return $true }   # 처리했으면 $true
    $false                                                                # 아니면 기본 동작
}
Set-WtMarkdownText $view $text
```

- `-Scroll`: 남는 높이를 채우고 스스로 스크롤합니다. 빼면 글 높이만큼 커집니다(바깥이 스크롤하는 화면).
- `-BaseDir`: 상대 경로 그림 · 파일 링크의 기준 폴더. 메모처럼 파일이 아닌 글은 비워 둡니다.
- `-OnLink`: 링크 · `[[위키 링크]]` · `#태그`를 눌렀을 때. 이게 있으면 태그도 누를 수 있게 그립니다. 처리하지 않은 링크의 기본 동작은 아래와 같습니다.
  - 웹 주소: `http` · `https` · `mailto`만 기본 브라우저 · 메일 프로그램으로 엽니다.
  - 파일: 폴더는 탐색기로, 문서 · 그림은 기본 프로그램으로 엽니다. 실행 파일 · 스크립트는 열지 않고 탐색기에서 그 파일을 보여 줍니다.
  - 같은 문서 안 제목(`[[#제목]]`, `(#제목)`) · 각주: 그 자리로 스크롤합니다.
- `-StrictLineBreaks`: 줄바꿈 한 번을 이어 붙입니다(표준 마크다운). 기본은 Obsidian처럼 줄을 바꿉니다.
- 더 붙이기: 코드 블록을 언어별로 따로 그리려면 `Register-WtMarkdownCodeRenderer`(Mermaid가 이렇게 붙어 있음), 콜아웃 종류는 `Register-WtMarkdownCallout`, 코드 색칠 언어는 `Register-WtCodeLanguage`.
- `Get-WtMarkdownSnippet`: 목록 한 줄 요약용으로 마크다운 기호를 뗀 글. `Get-WtMarkdownHeadings`: 제목 목록(목차용).

**되는 것**
- 기본: 제목, 굵게 · 기울임 · 취소선 · ==형광펜==, 인라인 코드, 링크 · 자동 링크, 목록(번호 · 안쪽), 인용, 가로줄, 표(정렬), 각주, 그림(로컬 파일만)
- Obsidian: 콜아웃 `> [!종류] 제목`(13종 + 별칭, `-` · `+` 접기), `[[위키 링크|별칭]]`, `![[그림.png|300]]`, `#태그`, `%%주석%%`, 맨 앞 `---` 속성, 할 일 `- [ ]`, 줄바꿈 한 번 = 줄바꿈
- GitHub 알림 `> [!NOTE]` · `[!TIP]` · `[!IMPORTANT]` · `[!WARNING]` · `[!CAUTION]`
- 코드 블록: 언어 이름 표시 + [복사], 색칠 14개 언어(PowerShell · Bash · Python · JavaScript/TypeScript · JSON · YAML · XML/HTML · SQL · C# · INI/TOML · diff · CSS · Dockerfile · Batch)
- Mermaid: flowchart · graph, sequenceDiagram, stateDiagram. 폭이 모자라면 줄여서 보여 줍니다.

**안 되는 것 (원문 · 글자로 보여 줌)**
- Mermaid의 다른 종류(gantt · classDiagram · pie · erDiagram …)와 색 꾸미기(`style` · `classDef`)
- 수식(`$…$`)은 그리지 않고 글자로, HTML 태그는 `<br>`만 줄바꿈으로 쓰고 나머지는 빼고 글자만
- 웹 주소의 그림은 내려받지 않고 이름과 링크로 보여 줍니다 (외부 통신 없음)

## 성능 설정과 측정

- 앱은 `DOTNET_TieredCompilation=0`으로 실행합니다. .NET이 뒤에서 코드를 다시 컴파일하는 동안 화면이 굼떠지는 것을 줄이는 성능 설정입니다([설명](https://learn.microsoft.com/en-us/dotnet/core/runtime-config/compilation#tiered-compilation)). 이 앱의 프로세스에만 적용되고, 실행 정책 · 보안 설정 · 레지스트리 · 사용자 환경 변수는 바꾸지 않습니다.
  - 개인 PC 실행 파일(`Start-WorkTool.cmd` · `start-dev.cmd`)은 GUI 프로세스에만 이 값을 넘깁니다.
  - 업무 PC에서 `.\WorkTool-WPF.ps1`로 켜면 같은 콘솔에서 이 설정으로 한 번 다시 실행합니다. 그만큼 시작이 조금 늦어집니다.
- 탭에 다시 들어올 때는 데이터나 설정이 바뀐 화면만 다시 만듭니다. 문서 · 활성 작업 · 업무 스크립트 목록은 들어올 때마다 다시 모읍니다.
- 앱을 켜고 첫 화면이 뜬 뒤, 한가할 때 아직 안 연 탭 · 설정 · 도움말 화면을 하나씩 미리 만들어 둡니다. 처음 누를 때도 다시 누를 때처럼 빨리 뜨게 하려는 것입니다. 화면 하나를 만든 뒤마다 쉬어서, 그사이 누른 것을 먼저 처리합니다. 어느 탭을 미리 만들지는 탭마다 정합니다(「탭(애드온) 더하기 · 빼기」의 `-WarmUp`).
- `tests/Measure-WtPerformance.ps1`은 창 없이 임시 데이터로 화면 만드는 비용을 짧게 확인합니다. 전체 검사에는 들어가지 않고, 실행 전에 사용자에게 범위를 알리고 허락을 받습니다(`AGENTS.md`).

  ```powershell
  pwsh -NoProfile -STA -File ./apps/WorkTool/wpf/tests/Measure-WtPerformance.ps1 -OutputPath ./.work/perf-light
  ```


## 이 창에서 쓰지 않는 것

- 창 투명도를 100%보다 낮게 고르면 테두리 없는 투명 창(AllowsTransparency)으로 띄웁니다. 투명 창은 ClearType을 쓸 수 없어 글자가 흐려지므로, 100%면 보통 창으로 띄웁니다. 투명 창 여부는 창을 띄울 때만 정할 수 있어서, 100%와 그 아래를 오가면 다시 시작해야 적용됩니다(설정 화면에 안내가 뜹니다). 투명 창일 수 있으므로 이 창 안에는 WinForms 컨트롤(WindowsFormsHost)이나 WebBrowser를 넣지 않습니다(그려지지 않음). 마크다운은 PowerShell 7에 들어 있는 Markdig로 읽어 WPF 문서(FlowDocument)로 그리고, Mermaid도 직접 배치해서 WPF 도형으로 그립니다.
- 윈도우 전체 단축키, 자동 실행 등록 등은 `AGENTS.md` 「코드 규칙」 4번에 따라 쓰지 않습니다.
