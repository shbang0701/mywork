# 화면 디자인 기준 (design.md)

GUI 화면의 **시각과, 시각으로 인한 사용자 경험**을 정합니다.
Microsoft의 Windows 앱 디자인 지침([Design guidelines](https://github.com/MicrosoftDocs/windows-dev-docs/blob/docs/hub/apps/design/guidelines-overview.md))을 우리 환경에 맞게 줄이고 고쳤습니다. 출처와 적용하지 않은 항목은 맨 아래 「출처」에 있습니다.

| 다룸 | 다루지 않음 (아직 정하지 않음) |
|---|---|
| 색 · 글자 · 간격 · 모양 · 층 · 아이콘 · 배치 · 탐색 구조 · 명령 배치 · 상태 표시 · 움직임 · 화면 문구 · 시각 접근성 | 내부 처리 · 렌더링 성능, 저장 · 자동 저장 · 실행 취소 구현, 단축키 체계, 키보드 탐색 순서, 보조 기술(UIA) 구현 |

**앱별 디자인 문서와의 관계**
- 이 문서는 `apps/` 아래 모든 GUI 앱의 공통 원칙입니다(접근성, 배치, 상태 표시, 문구, 움직임 등).
- 색 · 글꼴 · 크기 같은 **구체적인 값은 앱별 디자인 문서가 우선**합니다. WorkTool은 `apps/WorkTool/design/README.md`입니다.
- 이 문서의 색 표(3장)는 앱 문서가 아직 값을 정하지 않은 항목의 기본값입니다. 앱 문서와 다르면 앱 문서를 따르고, 대비 기준(4.5:1 등)은 양쪽 모두 지킵니다.

**읽는 법**
- 각 절의 `Windows 지침:` 줄은 원문 요약, 나머지는 우리 기준입니다.
- 색 · 크기 · 간격 · 시간은 이 문서의 토큰만 씁니다. 새 값이 필요하면 여기에 먼저 추가합니다.
- 이 문서에 없는 것은 Windows 기본 컨트롤(Fluent) 동작을 따릅니다.
- 단축키는 아직 정하지 않았습니다. 그때까지 Windows 표준 단축키(Ctrl+N · O · S · Z · Y · X · C · V · A · F · P, F2 이름 바꾸기, F5 새로 고침, Delete 삭제)만 쓰고, 새로 정한 단축키는 결과 보고에 적습니다.
- 규칙이 부딪히면 ① 접근성(대비, 색만으로 구분 금지) → ② 핵심 기능 노출 → ③ Windows 관습 → ④ 미관 순서로 정합니다.

## 1. 우리 환경

| 항목 | 내용 | 디자인에 주는 영향 |
|---|---|---|
| 사용자 | 사내 IT 인프라 담당자, 입문자부터 숙련자까지 | 핵심 기능은 보이게, 숙련자용은 단축키 · 명령 검색으로 |
| 언어 | 한국어 UI | 한글은 맑은 고딕. 화면 용어 = 문서 용어 = Windows 용어 |
| OS | 회사 Windows PC(10 · 11). FHD 노트북은 보통 화면 배율 125 · 150% | 4 epx 격자, 벡터 아이콘, 화면 배율별 검수 |
| 네트워크 | 인터넷(GitHub 열람)은 되지만 프로그램 설치 · 외부 패키지는 쓰지 않음 (`AGENTS.md`) | 외부 글꼴 · CDN · 온라인 도움말 없이 앱 안에서 완결 |
| 기존 산출물 | Excel 도면 · PPT 구성요소 · 아이콘 60종 (`docs/templates/infra-kit/README.md`) | 색 · 아이콘 · 용어의 뜻을 문서와 같게. 화면 = 문서 = 인쇄 |
| 기술 스택 | PowerShell 7 + WPF (첫 앱: `apps/WorkTool`, 지금은 WinForms에서 옮기는 중) | 단위는 epx(유효 픽셀) = WPF의 DIP = CSS px |

## 2. 원칙

1. **핵심 기능은 보인다.** 자주 쓰고 중요한 기능은 글자 라벨과 함께 항상 보이는 자리에 둡니다. 안쪽에 넣는 것은 가끔 쓰는 기능뿐입니다.
2. **보이는 것이 사용법이다.** 설명 문장을 쓰고 싶으면 UI부터 고칩니다.
3. **색은 뜻이 있을 때만.** 기본은 회색, 강조색은 하나. 넓은 면은 차분하게, 진한 색은 작은 면적에만 씁니다.
4. **중요한 것만 눈에 띈다.** 위계는 크기 · 굵기 · 진하기로 만들고, 단계를 늘리지 않습니다.
5. **Windows답게.** 익숙한 위치 · 모양 · 동작을 따르고, 새 조작법을 만들지 않습니다.
6. **장식보다 구조.** 정렬 · 여백 · 글자로 정돈합니다. 그라디언트, 장식용 그림자, 흉내 낸 유리 효과는 쓰지 않습니다.
7. **화면 = 문서.** 용도 색 · 상태 색 · 아이콘 · 용어를 Excel · PPT와 같은 뜻으로 씁니다.
8. **기다림이 보인다.** 누르면 바로 반응하고, 오래 걸리면 진행을 보여 주며, 화면이 갑자기 밀리지 않습니다.

## 3. 색

`Windows 지침:` 색은 위계와 구조를 보여 주는 데 쓰고, 강조색은 중요한 요소와, 상호작용 요소의 상태(선택 · 켜짐)에만 아껴 씁니다. 상호작용을 뜻하는 색은 하나로 정합니다. 덜 중요한 면은 어둡게, 중요한 면은 밝게 둡니다.

### 3.3 상태 색 (라이트)

| 상태 | 아이콘 · 채움 | 글자 | 연한 바탕 |
|---|---|---|---|
| 정상 | `#1E7F47` | `#1A6E3E` | `#E6F4EC` |
| 주의 | `#A86500` | `#8A5300` | `#FCF2DE` |
| 장애 | `#C42F29` | `#B42820` | `#FBE9E7` |
| 정보 | `#1A5BBE` | `text.primary` | `#E8F0FC` |

- 상태는 항상 **색 + 아이콘 + 글자** 세 가지로 표시합니다.
- 아이콘 · 채움 색은 WorkTool 2판의 C 값입니다. 문서의 주의 `#D98E04` 대신 화면 아이콘에는 `#A86500`을 씁니다.
- 글자색은 연한 바탕과 흰 바탕 모두에서 4.5:1 이상입니다. 문서 색을 글자로 쓰면 정상 · 장애는 3.7 ~ 4.2:1, 주의는 2.4:1로 부족합니다.
- 화면 틀의 알림 막대는 Windows 기본 아이콘을, 도면 · 목록 속 장비 상태는 `docs/templates/infra-kit/03_아이콘`의 57 정상 · 50 경고(= 주의) · 58 장애 · 59 정보를 씁니다.
- 정보 글자는 링크와 헷갈리지 않게 `text.primary`로 씁니다.
- 연한 바탕은 알림 막대 · 상태 배지에만 씁니다. 표 · 목록 행 전체를 칠하지 않습니다(정보의 연한 바탕은 `bg.selected`와 같은 색). 표 · 목록에서는 '상태' 열에 상태 아이콘 16 + 글자로 표시합니다.
- 장비 아이콘 위 상태 배지는 32 이상 아이콘에만 겹칩니다. 크기는 장비 아이콘의 1/2, 자리는 오른쪽 아래, 바깥 2를 바탕색으로 떼어 냅니다. 상태 색과 남색의 대비가 2.2 ~ 3.0:1이라 붙이면 묻힙니다.
- `docs/templates/infra-kit/03_아이콘/svg`는 모두 남색(`#1F3A5F`)으로 칠해져 있습니다. 화면에서는 SVG의 채움 색을 실행 중에 바꿔 씁니다.

### 3.4 도면 영역 (캔버스)

- 종이는 `#FFFFFF`, 격자는 `#E4E9EF`, 종이 바깥은 `bg.base`입니다. **다크 모드에서도 종이는 흰색입니다.** 인쇄물 · PPT와 색의 뜻을 맞추기 위해서입니다.
- 도면 안의 글자 · 선 · 모서리는 문서 기준(README 「도면 기준」, PPT 「디자인 기준」 슬라이드)을 따릅니다. 화면 틀 규칙(모서리 4 · 8 등)을 도면 안에 적용하지 않습니다.
- 용도 · 연결 색과 선 모양은 문서와 똑같이 씁니다.

| 용도 | 색 | 선 (PPT 연결선 기준) |
|---|---|---|
| 서비스 | `#2F6DB5` | 실선 1.75pt |
| 스토리지 (SAN) | `#BF5B14` | 실선 1.75pt |
| 관리 (OOB) | `#0B7C7C` | 짧은 파선 `sysDash` 1.25pt |
| 백업 | `#377F3F` | 긴 파선 + 점 `lgDashDot` 1.25pt |
| HA · 스택 · 피어링크 | `#7A55B3` | 점선 `sysDot` 1.25pt |
| 복제 · DR | `#7A55B3` | 긴 파선 `lgDash` 1.75pt |
| WAN · 인터넷 | `#3A4856` | 실선 2.25pt |
| 전원 | `#C73E3A` | 실선 1.25pt |
| 콘솔 | `#5E6B78` | (포트 색만) |

- 선택은 2 `accent` 외곽선과 8 × 8 손잡이(흰 채움, `accent` 테두리)로 표시합니다. 색만 바꿔서 선택을 나타내지 않습니다.
- 읽을 수 없는 글자는 그리지 않습니다. 화면에서 8px보다 작아지는 확대/축소 비율에서는 포트명 · 디스크 용량 같은 작은 글자를 생략하고, 확대하거나 마우스를 올리면 보여 줍니다.

### 3.5 색 규칙

- 넓은 면에는 `bg.*`(회색 계열)만 씁니다. 진한 색은 버튼 · 막대 · 아이콘 · 선 같은 작은 면적에만 씁니다.
- 강조색은 "누를 수 있음 · 선택됨"을 뜻합니다. 장식으로 쓰지 않습니다.
- 용도 색 · 상태 색은 도면 · 상태 표시 · 차트(3.6)에만 씁니다. 화면 틀 장식에 쓰지 않습니다. 서비스 파랑과 강조색이 비슷한 파랑이라 특히 주의합니다.
- Windows 사용자 강조색(개인 설정)은 따르지 않습니다. 용도 색과 겹치면 뜻이 섞입니다(예: 주황 강조색 = 스토리지).
- 문서와 공유하는 색의 원본은 `docs/templates/infra-kit/_build/ppt_kit.py` · `docs/templates/infra-kit/_build/xlkit.py`의 `P`입니다. 바꾸면 이 문서의 표도 함께 고칩니다.

### 3.6 차트

차트 종류는 `ui-ux-pro-max`의 `--domain chart`로 고르고, 색은 아래 값만 씁니다.

| 계열 | 라이트 | 다크 |
|---|---|---|
| 하나 | `brand` `#1F3A5F` | `text.secondary` `#A9B4C1` |
| 상태별 (정상 · 주의 · 장애 · 정보) | 3.3의 아이콘 · 채움 색 | 3.2의 상태 색 |
| 용도별 (서비스 · 스토리지 등) | 3.4의 용도 색 + 선 모양 | 차트 바탕을 흰 종이로 두고 라이트 값 그대로 |
| 그 밖의 여러 계열 | 강조할 한 계열만 `brand`, 나머지는 `#7F8C9C` | 강조할 한 계열만 `text.primary`, 나머지는 `#75828F` |

- 계열이 하나여도 상태를 뜻하면(예: 장애 건수) 상태별 색을 씁니다. `brand`는 뜻이 없는 한 계열에만 씁니다.
- 계열은 색과 함께 선 모양 · 표식 · 직접 라벨로도 구분합니다(15장). 범례보다 선 끝의 직접 라벨을 먼저 씁니다.
- 축 · 눈금 글자는 캡션 · `text.secondary`, 격자선은 `border.subtle`입니다.
- 뜻이 없는 여러 계열에 용도 색 · 상태 색을 쓰지 않습니다. 뜻이 섞입니다. 계열이 많으면 차트를 나눕니다.

## 4. 글자

`Windows 지침:` 앱 전체에 글꼴 하나를 쓰고, 형식 단계(type ramp)로 위계를 만듭니다. 강조는 Bold 대신 Semibold, 기울임꼴은 쓰지 않습니다. 왼쪽 정렬이 기본이고, 최소 크기는 보통 굵기(Regular) 12px · Semibold 14px입니다. Windows의 한국어 UI 글꼴은 맑은 고딕입니다.

### 4.1 글꼴

| 쓰는 곳 | 글꼴 | 이유 |
|---|---|---|
| 화면 틀 | `Segoe UI Variable`(Windows 11) → `Segoe UI`(Windows 10), 한글은 `맑은 고딕` | Windows 기본 UI 글꼴. 반입 · 설치할 것이 없음 |
| 화면 틀의 IP · MAC · 시리얼 · 케이블 라벨 | `Consolas` | 0과 O, 1과 l이 구분됨 |
| 도면 안 | `맑은 고딕`, 케이블 라벨만 `Consolas` | Excel · PPT와 같음 |

- CSS 글꼴 순서: `"Segoe UI Variable Text", "Segoe UI", "Malgun Gothic", sans-serif`. WinUI는 기본값 그대로 둡니다.
- 외부 글꼴(Pretendard 등)은 넣지 않습니다.

### 4.2 형식 단계 (epx)

| 이름 (WinUI 스타일) | 크기 / 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| 캡션 `Caption` | 12 / 16 | 보통 | 단축키 표시 · 상태 표시줄 · 보조 정보 · 두 줄 목록의 둘째 줄 · 좁은 버튼 |
| 본문 `Body` | 14 / 20 | 보통 | 기본. 컨트롤 · 표 · 목록 · 속성 |
| 본문 강조 `BodyStrong` | 14 / 20 | 강조 | 표 머리글 · 좁은 패널(탐색 · 목록 · 속성)의 제목과 구역 제목 · 경로 표시의 마지막 항목 |
| 소제목 `Subtitle` | 16 / 24 | 강조 | 넓은 내용 영역의 구역 제목 · 대화상자 제목 |
| 제목 `Title` | 20 / 28 | 강조 | 설정 · 개요 같은 페이지의 제목, 화면당 하나. 목록/상세 · 편집 화면은 경로 표시가 제목을 대신함 |

- 단계는 이 5개만 씁니다. 한 패널 안에서는 패널 제목을 빼고 3단계까지만 씁니다.
- 굵기는 **보통 · 강조** 두 가지입니다. 강조 = Semibold(600)입니다. 맑은 고딕에는 600이 없어 한글은 Bold로 보이므로, 강조는 위 표에 적힌 자리(머리글 · 제목)에만 쓰고 나머지 위계는 **크기와 진하기**로 만듭니다.
- 같은 크기 안에서는 `text.primary` / `text.secondary`로 나눕니다.
- 기울임꼴은 쓰지 않습니다. 맑은 고딕에는 기울임꼴이 없어 억지로 기울어집니다.

### 4.3 글자 배치

- 왼쪽 정렬이 기본입니다. 가운데 정렬은 아이콘 아래 이름처럼 드문 경우에만 씁니다.
- 글자가 넘치면 말줄임(…)으로 줄이고, 마우스를 올리면 전체를 보여 줍니다.
- **IP · 시리얼 · 케이블 라벨 · 도면 번호는 자르지 않습니다.** 잘린 값은 틀린 값입니다. 표에서는 줄을 바꾸지 않고 열의 최소 폭을 값 전체에 맞춥니다(가로 스크롤 허용). 줄바꿈은 상세 · 속성 패널에서만 씁니다.
- 수량 · 위치 번호(용량 · U 위치 · U 수 · 개수)는 오른쪽 정렬, 식별자(IP · 시리얼 · 포트명)는 왼쪽 정렬합니다. 숫자는 고정폭(tabular)으로 씁니다.
- 여러 줄 한글은 메모 기준 줄 간격 1.6배(15/24), 폭 680 이하, 단어 단위 줄바꿈(`keep-all`)로 씁니다.
- 용량 표기는 문서와 같게 씁니다: `1.92T SSD`.

## 5. 간격 · 크기 · 모양

`Windows 지침:` 크기 · 여백 · 위치는 모두 4 epx의 배수로 맞춥니다. 그래야 화면 배율 100 ~ 400%에서 픽셀이 딱 맞아 가장자리가 선명합니다. 글자는 예외입니다. 창 · 메뉴 · 대화상자는 8, 버튼 · 입력칸 같은 화면 안 요소는 4로 모서리를 둥글립니다.

### 5.1 간격

| 관계 | 값 |
|---|---|
| 버튼 사이 · 버튼과 펼침 메뉴 사이 | 8 |
| 컨트롤과 위쪽 머리글 | 8 |
| 컨트롤과 옆 라벨 | 12 |
| 카드 사이 (설정 · 개요 화면) | 12 |
| 카드 · 대화상자 가장자리와 글자 | 12 |
| 편집 · 목록 화면 패널의 안쪽 여백 | 12 (도구형 앱 — Windows 메모장 · 터미널과 같음) |

- 간격은 4 · 8 · 12 · 16 · 24 · 32만 씁니다.
- 묶음 안은 좁게(4 · 8), 묶음 사이는 넓게(12 이상) 둡니다. 구분선보다 여백으로 먼저 나눕니다.

### 5.2 크기

높이는 모두 최소값입니다. 텍스트 크기 설정에 따라 함께 커집니다.

| 요소 | 값 |
|---|---|
| 제목 표시줄 | 32 (검색 상자 · 사용자 사진을 넣으면 48) |
| 메뉴 막대 · 명령 모음 · 경로 표시줄 · 상태 표시줄 | 32 · 40 · 40 · 24 |
| 버튼 · 입력칸 · 드롭다운 높이 | 32 (작은 찾기 칸 · 아이콘 버튼 · 달 이동은 28) |
| 표 행 | 32 |
| 목록 항목 | 한 줄 32 · 두 줄 48 (본문 + 캡션, 앞 아이콘 14). WorkTool 메모는 두 줄 52 |
| 아이콘만 있는 버튼 | 28 × 28. 입력칸 옆 파일 선택은 32 × 32 |
| 패널 폭 | 탐색 200(최소 200) · 목록 240~280 · 속성 220~308(최소 220) · 내용 최소 360. 경계를 끌어 조절하고, 바꾼 폭은 기억함 |

### 5.3 모서리 · 선

| 반지름 | 쓰는 곳 |
|---|---|
| 8 `radius.overlay` | 창 · 대화상자 · 메뉴 · 펼침 패널 |
| 4 `radius.control` | 버튼 · 입력칸 · 목록 항목 바탕 · 카드 · 툴팁 · 진행 막대 · 스크롤 막대 (작은 체크 상자 · 칩 · 막대는 2) |
| 0 | 다른 직선 변과 맞닿는 변(분할 버튼의 두 부분, 맞붙은 패널, 표 행의 선택 바탕 등) · 최대화 · 스냅된 창 |

- 선 두께(테두리 1, 포커스 2 + 1, 선택 막대 3)는 4의 배수 규칙에서 예외입니다.
- 포커스는 Windows 고가시성 포커스를 따릅니다: 바깥 2, 안쪽 1, 요소에서 1 띄움. 가장자리에 닿는 요소(표 행 · 목록 항목 · 패널 끝)는 잘리지 않게 안쪽에 그립니다.

### 5.4 표

- 머리글은 `BodyStrong`, 아래에 1 `border.muted`를 둡니다.
- 행 사이에 1 `border.muted`를 둡니다(구분선을 쓰는 예외).
- 셀 좌우 여백은 12입니다.
- 선택된 행은 `bg.selected`를 행 전체에 모서리 0으로 칠하고, 왼쪽에 강조색 막대를 둡니다.

## 6. 층 · 그림자 · 재질

`Windows 지침:` 앱은 두 층입니다. **아래층(base)**에는 메뉴 · 명령 · 탐색을, **위층(content)**에는 앱의 주 작업을 둡니다. 그림자와 윤곽선은 높이(떠 있는 정도)를 알리는 데 쓰고, 장식으로 쓰지 않습니다. 많이 쓰면 효과가 약해집니다. 재질로는 Mica(불투명, 바탕화면 색이 살짝 섞임)와 Acrylic(반투명, 메뉴처럼 잠깐 뜨는 면)이 있습니다. 둘 다 고대비 · 투명 효과 끔 · 배터리 절약 모드에서 단색으로 바뀌고, Mica는 Windows 10(빌드 22000 미만)에서도 단색입니다.

| 층 | 바탕 | 테두리 | 그림자 (Windows 높이 값) |
|---|---|---|---|
| 아래층 | `bg.base` | — | 없음 |
| 위층 · 카드 · 패널 | `bg.content` | `border.subtle` | 없음 |
| 툴팁 | `bg.raised` | `border.subtle` | 없음 (0) |
| 메뉴 · 펼침 패널 · 끌고 있는 도면 객체 | `bg.raised` | `border.subtle` | 없음 (0) |
| 대화상자 | `bg.raised` | `border.subtle` | 없음 (0) + 뒤를 반투명 검정으로 어둡게 |

- WinUI는 기본 그림자(ThemeShadow)를 그대로 씁니다. 다른 스택은 아래 값을 씁니다.
  - 작게: `none` (0)
  - 중간: `none` (0)
  - 크게: `none` (0)
- 그림자는 떠 있는 것(툴팁 · 메뉴 · 대화상자 · 끌고 있는 객체)에만 씁니다. 카드 · 패널은 그림자 대신 1 테두리만 씁니다(문서도 그림자를 쓰지 않습니다).
- 편집 · 목록/상세 화면의 패널은 맞붙이고 1 `border.subtle`로 나눕니다. 12 간격의 카드는 설정 · 개요처럼 내용을 묶어 보여 줄 때만 씁니다.
- 재질(Mica · Acrylic)은 쓰지 않습니다. WinUI도 창 바탕은 `bg.base` 단색(SystemBackdrop 없음), 메뉴 · 펼침 패널은 `bg.raised` 단색입니다. 바탕화면 색이 섞이고 Windows 10 · 투명 효과 끔에서 모양이 달라지기 때문입니다.
- WinUI 기본 컨트롤이 쓰는 강조색 리소스(`SystemAccentColor` 계열)는 `accent` 계열 토큰으로 덮어쓰고, 알림 막대(InfoBar) 색은 3.3 값을 씁니다.

## 7. 아이콘

`Windows 지침:` 명령 · 탐색 · 상태에는 시스템 아이콘 글꼴(Segoe Fluent Icons, 1 epx 단선)을 씁니다. 글꼴 크기 16 epx = 16 × 16 아이콘입니다. 꼭 필요한 세부만 넣고 익숙한 은유를 씁니다. 상태 같은 수정자는 기본 아이콘의 아래쪽 사분면에 둡니다. Segoe Fluent Icons는 Windows 10에 기본 설치되어 있지 않습니다.

| 종류 | 출처 | 모양 | 크기 (epx) | 쓰는 곳 |
|---|---|---|---|---|
| 명령 · 탐색 · 알림 | `Segoe Fluent Icons`(Windows 11) · `Segoe MDL2 Assets`(Windows 10) | 단선 | 16 (버튼 · 메뉴 · 탐색) | 명령 모음 · 메뉴 · 탐색 · 알림 막대 |
| 장비 · 개념 | `docs/templates/infra-kit/03_아이콘/svg` (60종, 48 격자) | 채움, `brand` 남색 / 다크 · 진한 바탕엔 `text.primary` | 24 (표) · 32 (목록) · 48 (도면 · 카드) | 도면 · 장비 목록 · 부품 상자 |

- 두 종류를 섞지 않습니다. 명령 버튼에 장비 아이콘을, 도면에 단선 아이콘을 쓰지 않습니다.
- 아이콘 글꼴은 시스템에 있는 것을 쓰고, 따로 반입하거나 번들하지 않습니다.
- 장비 아이콘은 SVG(벡터)로 씁니다. 화면 배율 125 · 150%에서도 선명합니다.
- 장비 상태는 기본 아이콘의 오른쪽 아래 사분면에 상태 배지를 겹쳐 표시합니다(예: 서버 + 장애). 크기와 떼어 내기는 3.3을 따릅니다.
- 아이콘만 있는 버튼은 누구나 아는 것(실행 취소 · 다시 실행 · 닫기 · 확대 · 축소)에만 씁니다. 나머지는 아이콘 + 글자입니다. 예외: 창 폭 1008 미만에서는 명령 모음의 글자를 빼고 아이콘만 남길 수 있습니다(8.1). 아이콘만 있는 버튼에는 `이름 (단축키)` 툴팁을 답니다.

## 8. 배치 · 창 크기

`Windows 지침:` 화면 크기가 아니라 **창 크기**에 맞춥니다. 기준 폭은 640 · 1008입니다. 창 크기에 따라 위치 바꾸기 · 크기 바꾸기 · 다시 흐르기 · 보이기/숨기기 · 구조 바꾸기를 씁니다. 제목 표시줄 표준 높이는 32입니다.

### 8.1 기준 창

| 기준 | 크기 (epx) | 요구 |
|---|---|---|
| 기본 검수 크기 | 1280 × 672 | FHD 노트북 화면 배율 150%에서 최대화한 크기(작업 표시줄 제외). **핵심 기능이 스크롤 없이 모두 보여야 함** |
| 큰 화면 | 1920 × 1032 | FHD 100%. 패널을 더 펼쳐 이동을 줄임 |
| 최소 창 | 640 × 480 | 이보다 작게 줄어들지 않음 |

| 창 폭 | 배치 |
|---|---|
| 1008 이상 | 탐색 · 내용 · 속성 패널을 모두 펼침 |
| 641 ~ 1007 | 탐색 · 속성 패널은 접히고, 열면 내용 위에 겹쳐 뜸(펼침 패널 층: `bg.raised` · 그림자 없음 · 모서리 8, 창 가장자리 쪽은 0 · 나타남 0 ms) |
| 640 | 내용 한 열, 패널은 겹쳐 뜨는 방식만. 목록/상세는 목록 → 상세로 화면을 바꿈 |

- 좁아져도 **핵심 명령은 남습니다.** 글자가 빠지고 아이콘 + 툴팁만 남을 수는 있지만, 더 보기(⋯)로 들어가는 것은 보조 명령뿐입니다.
- 넓어져서 남는 공간에는 정보를 더 보여 줍니다. 빈 여백만 늘리지 않습니다.
- 화면 배율 100 · 125 · 150 · 200%에서 흐림 · 잘림 · 겹침이 없어야 합니다. 화면 배율이 다른 모니터 사이로 창을 옮겨도 선명해야 합니다(모니터별 DPI).

### 8.2 편집 화면 틀

도면 · 구성도처럼 캔버스가 있는 화면의 틀입니다. Windows의 "메뉴 막대" 실루엣(메모장처럼 작업 중심)을 따릅니다.

```
┌ 제목 표시줄 32 ──────────────────────────────────────┐  아래층
│ 메뉴 막대 32 + 명령 모음 40                            │  아래층
│ 경로 표시줄 40: DC1 › R02 › U20 SRV-01                │  아래층
├──────────┬───────────────────────────┬───────────────┤
│ 목록·트리 │ 캔버스                     │ 속성 패널       │  위층
│ 280      │ (최소 360)                 │ 280            │  (맞붙이고 1 구분선)
├──────────┴───────────────────────────┴───────────────┤
│ 상태 표시줄 24: 저장 상태 · 선택 개수 · 확대/축소       │  아래층
└──────────────────────────────────────────────────────┘
```

- 앱의 최상위 탐색(페이지 전환)이 있으면 아래층 왼쪽에 둡니다.

### 8.3 목록/상세 화면 틀

랙 목록 · 장비 목록처럼 항목을 고르고 내용을 보는 화면의 틀입니다.

```
┌ 제목 표시줄 32 ──────────────────────────────────────┐  아래층
│ 메뉴 막대 32 + 명령 모음 40                            │  아래층
│ 경로 표시줄 40: DC1 › R02                              │  아래층
├──────────┬───────────────────────────┬───────────────┤
│ 랙 목록   │ 장비 표 (행 32)             │ 속성 패널       │  위층
│ 두 줄 48  │                           │ (선택한 장비)   │
├──────────┴───────────────────────────┴───────────────┤
│ 상태 표시줄 24: 저장 상태 · 선택 개수                   │  아래층
└──────────────────────────────────────────────────────┘
```

- 기준 창 1280 × 672에서 표 영역의 높이는 504입니다(위아래 막대 168을 뺀 값).
- 경로 표시가 화면 제목을 대신합니다. 마지막 항목은 `BodyStrong`, 앞 항목은 누를 수 있는 링크입니다.
- 랙을 고르면 같은 자리에서 장비 표를 바꿉니다. 새 탭은 [새 탭에서 열기]로만 엽니다.

### 8.4 속성 패널

- 라벨은 입력칸 위(8 간격)에 둡니다. 편집할 수 있는 값은 항상 입력칸으로 보이고, 읽기 전용 값은 입력칸 없이 `text.primary` 글자로 씁니다.
- 입력칸 값은 Enter를 누르거나 다른 칸으로 옮길 때 반영되고, 한 번의 실행 취소로 되돌립니다. 체크박스 · 드롭다운은 바꾸는 즉시 반영됩니다.
- 형식이 틀린 값은 반영하지 않고, 칸 바로 아래에 오류를 한 줄로 보여 줍니다.
- 필수 입력은 라벨 뒤에 `(필수)`를 붙입니다.
- 예시값은 `예: 10.0.12.5`처럼 `예:`를 붙여 `text.secondary`로 씁니다. 실제 값으로 오해하지 않게 하기 위해서입니다.
- 선택이 없으면 `장비를 선택하세요.` 한 줄을 보여 줍니다.
- 여러 개를 고르면 맨 위에 `3개 선택됨`을 보이고, 값이 같은 칸만 채웁니다. 값이 다르면 `(여러 값)`을 `text.secondary`로 씁니다.

## 9. 탐색

`Windows 지침:` 일관성 · 단순함 · 명확함이 원칙입니다. 같은 수준의 페이지가 7개 이하면 평평하게, 그보다 많으면 계층으로 나눕니다. 최상위 항목이 5개를 넘으면 왼쪽 탐색을 씁니다. 2단계를 넘으면 경로 표시(breadcrumb)를 둡니다. 위로 올라갔다 다시 내려오는 이동(pogo-sticking)을 피합니다. 자주 오가는 항목은 목록/상세 패턴으로 보여 주고, 목록 안에서 항목을 바꿔 고르는 것은 "뒤로" 기록에 남기지 않습니다.

- 우리 계층은 **센터 › 랙 › 장비**(3단계)이므로 경로 표시를 항상 보여 줍니다. 예: `DC1 › R02 › U20 SRV-01`
- 랙 목록 · 장비 목록은 목록/상세로 보여 줍니다. 목록을 남긴 채 옆에 상세를 띄웁니다.
- 위로 돌아가지 않고 바로 가는 링크를 둡니다: 케이블 반대쪽 장비, 같은 시스템의 다른 박스.
- 여러 파일(랙)을 동시에 열 수 있으면 탭으로 보여 줍니다. 새 탭은 [새 탭에서 열기]로만 엽니다.
- 현재 위치가 항상 보여야 합니다: 선택된 탐색 항목(강조색 막대) · 화면 제목 · 경로 표시.
- 대화상자 · 펼침 패널, 그리고 목록에서 다른 항목을 고르는 것은 "뒤로" 기록에 남기지 않습니다. 뒤로 · Esc를 누르면 대화상자 · 펼침 패널이 닫힙니다.

## 10. 명령 배치

`Windows 지침:` 내용을 직접 조작하게 하는 것이 먼저입니다(끌어서 놓기 등). 핵심 작업에 늘 필요한 명령은 대상 가까이에, 덜 쓰는 것은 메뉴 · 우클릭 메뉴에 둡니다. 되돌릴 수 없고 결과가 큰 작업만 확인을 받고, 되돌릴 수 있는 작업은 실행 취소로 충분합니다.

| 사용 빈도 × 중요도 | 자리 | 표시 |
|---|---|---|
| 핵심 작업에 늘 필요 | 대상 바로 옆 또는 명령 모음 앞쪽 | 아이콘 + 글자 |
| 자주 쓰는 보조 | 명령 모음 | 아이콘 + 글자 + 툴팁 (창 폭 1008 미만에서는 아이콘 + 툴팁) |
| 가끔 | 메뉴 · 우클릭 메뉴 · 더 보기(⋯) | 글자 + 단축키 |
| 모든 명령 | 명령 검색 | 이름으로 찾기 |

- 직접 조작(장비를 끌어 랙에 놓기, 순서 바꾸기)을 먼저 주고, 같은 일을 명령으로도 할 수 있게 합니다.
- 메뉴 항목 오른쪽에 단축키를 캡션 · `text.secondary`로 표시합니다. 입문자가 보다 보면 숙련자가 됩니다.
- **쓸 수 없는 명령은 숨기지 않고 비활성으로 보여 줍니다.** 마우스를 올리면 이유를 한 줄로 알려 줍니다. 예: `장비를 먼저 선택하세요`
- 강조색 버튼(주 행동)은 화면당 하나입니다.
- 같은 명령은 어디서나 같은 이름 · 같은 아이콘 · 같은 자리입니다.

| 확인 대화상자 (되돌릴 수 없고 결과가 큼) | 바로 실행 + 실행 취소 (되돌릴 수 있음) |
|---|---|
| 파일 덮어쓰기 · 저장하지 않고 닫기 · 디스크에서 지우기(랙 파일 삭제 등) | 장비 삭제(목록 · 표 · 도면 · 상세 어디서든) · 이동 · 이름 바꾸기 · 편집 |

- 확인 대화상자 예: `랙 R02를 삭제할까요?` [삭제] [취소]

## 11. 상태 · 반응 표시

`Windows 지침:` 명령의 결과는 UI 안에서 자연스럽게, 흐름을 끊지 않게 알려 줍니다. 다른 곳에서 이미 알 수 있으면 알리지 않습니다. 대화상자는 흐름을 끊으므로 꼭 필요할 때만 씁니다.

- 모든 화면에 네 가지 상태를 설계합니다: **불러오는 중 · 비어 있음 · 오류 · 정상**
- 비어 있음은 한 줄과 행동 버튼으로 보여 줍니다. 예: `랙이 없습니다` [랙 추가]
- 누를 수 있는 모든 요소에는 마우스 올림 · 눌림 · 포커스 · 비활성 상태가 있습니다. **누를 수 없는 것에는 마우스 올림 덧칠과 손 모양 커서를 주지 않습니다.** 반응하면 누를 수 있다는 뜻이 됩니다. 툴팁(잘린 글자 전체 · 비활성 이유 · 이름)은 예외입니다.
- 저장 상태(`저장됨` / `저장 안 됨`)는 항상 보입니다.
- 화면이 갑자기 밀리지 않게, 불러올 내용의 자리를 최종 배치와 같은 모양으로 미리 잡습니다.

| 걸리는 시간 | 표시 |
|---|---|
| 즉시 | 누르는 순간 눌림 상태 |
| 1초 넘음 | 그 자리에 진행 표시 (길이를 알면 막대, 모르면 링) |
| 10초 넘음 | 진행 표시 + 취소 버튼, 다른 작업은 계속할 수 있음 |

| 알릴 내용 | 자리 |
|---|---|
| 확인만 하면 되는 결과 (저장됨) | 상태 표시줄에 조용히 |
| 해결할 때까지 알아야 하는 문제 (연결 실패) | 화면 위 알림 막대, 해결되면 사라짐 |
| 되돌릴 수 없는 결정 | 대화상자 |
| 입력 오류 | 그 칸 바로 아래 한 줄 |

## 12. 보이는 것이 사용법 (설명 줄이기)

`Windows 지침:` 기본 기능을 가르치는 안내는 쓰지 않습니다. 안내가 필요하다면 디자인을 더 직관적으로 만들어야 한다는 뜻입니다. 안내를 쓸 때도 짧게, 관련된 순간에, 흐름을 막지 않게, 반복하지 않게 합니다.

| 설명을 쓰는 대신 | 이렇게 |
|---|---|
| "끌어서 옮길 수 있습니다" | 손잡이(⋮⋮)를 보여 주고, 마우스를 올리면 커서가 바뀜 |
| "더블클릭하면 편집됩니다" | 마우스를 올리면 편집 칸처럼 테두리가 생김 |
| "적용을 눌러야 반영됩니다" | 적용 버튼 없이 반영하고(입력칸은 Enter · 다른 칸으로 이동할 때), 실행 취소로 되돌림 |
| "여기에 IP를 입력하세요" | 칸 안에 `예: 10.0.12.5`를 `text.secondary`로 |
| "결과가 이렇게 바뀝니다" | 마우스를 올리면 미리보기 |
| 처음 실행 안내 팝업 | 빈 화면의 한 줄 + 행동 버튼 |

- 드러나지 않는 조작처럼 안내가 꼭 필요하면: 한 문장, 관련된 순간에, 무시해도 진행 가능하게, 한 번만.
- 도움말은 앱 안에 둡니다. 폐쇄망이므로 외부 링크를 걸지 않습니다.

## 13. 화면 문구

`Windows 지침:` 중요한 것을 먼저, 능동형으로, 짧게 씁니다. 사용자를 탓하지 않고 해결책을 줍니다. 버튼은 몇 단어 이내의 동작으로 씁니다. 대화상자의 제목(질문)과 버튼(답)이 맞물려야 합니다. 버튼 · 라벨 · 체크박스에는 마침표를 찍지 않고, 문장인 툴팁 · 오류 · 대화상자에는 찍습니다.

- **핵심 먼저, 한 문장.**
  - ✗ `케이블을 연결하고 싶으시다면 먼저 연결할 포트를 선택하신 후 진행하시기 바랍니다.`
  - ✓ `포트를 선택해 케이블을 연결하세요.`
- 문체: 문장은 `-습니다` · `-하세요`, 질문은 `-할까요?`로 씁니다(README와 같은 문체).
- 버튼 · 메뉴 · 라벨은 마침표 없이 1 ~ 2단어의 동작으로 씁니다.
- Windows 표준 용어를 씁니다: 새로 만들기 · 열기 · 저장 · 다른 이름으로 저장 · 닫기 · 인쇄 · 실행 취소 · 다시 실행 · 잘라내기 · 복사 · 붙여넣기 · 삭제 · 이름 바꾸기 · 모두 선택 · 찾기 · 바꾸기 · 가져오기 · 내보내기 · 새로 고침 · 설정 · 속성 · 다시 시도
- 도메인 용어는 문서와 같게 씁니다: 전면 · 후면 · 면 · 도면 번호 · 포트명 · 케이블 라벨 · 시스템 · 선반 · 용도(서비스 · 관리 · 백업 · 스토리지 · 인터커넥트 · 콘솔 · 전원). 새 약어는 만들지 않고, 현장 약어(SAN · OOB · iLO · RAID 등)는 그대로 씁니다.
- 오류는 무엇이 안 됐는지와 어떻게 하면 되는지를 씁니다. 기술 코드는 `자세히` 안으로 넣습니다.
  - ✗ `잘못된 입력입니다.` → ✓ `IP 형식이 아닙니다. 예: 10.0.12.5`
  - ✗ `오류 0x80070005` → ✓ `저장하지 못했습니다. 폴더 쓰기 권한을 확인하세요.` [다시 시도]
- 대화상자는 제목 = 질문, 버튼 = 답(동작)입니다. `예` / `아니요`는 쓰지 않습니다.
  - `변경 내용을 저장할까요?` → [저장] [저장 안 함] [취소] (Windows 순서: 주 버튼이 왼쪽)

## 14. 움직임

`Windows 지침:` 움직임은 빠르고 직접적이며 상황에 맞아야 합니다. 입력에 피드백을 주고 상태 사이를 이어 줍니다. 같은 입구로 여는 화면은 같은 방식으로 열고 닫습니다. 직접 만들기보다 기존 컨트롤의 애니메이션을 씁니다.

| 시간 토큰 | 값 | WinUI 이름 |
|---|---|---|
| `motion.faster` | 0 ms | `ControlFasterAnimationDuration` |
| `motion.fast` | 0 ms | `ControlFastAnimationDuration` |
| `motion.normal` | 0 ms | `ControlNormalAnimationDuration` |
| `motion.slow` | 0 ms | — |

| 곡선 | 값 | 쓰는 곳 |
|---|---|---|
| 나타남 | `cubic-bezier(0, 0, 0, 1)` | 들어오는 요소 (0) |
| 이동 | `cubic-bezier(0.55, 0.55, 0, 1)` | 있던 요소의 위치 · 크기 변화 (0) |
| 사라짐 | `cubic-bezier(1, 0, 1, 1)`, 또는 나타남 곡선 + 페이드 | 나가는 요소 (0) |
| 페이드 | 선형 | 투명도만 (0) |

- 333 ms를 넘기지 않습니다. 튀는 효과(탄성)와 장식 애니메이션은 쓰지 않습니다.
- 같은 입구는 같은 움직임입니다. 예: 오른쪽 패널은 모두 오른쪽에서 열리고 오른쪽으로 닫힙니다.
- 직접 조작(끌기 · 확대/축소 · 스크롤)은 지연 없이 손을 그대로 따라갑니다.
- Windows의 애니메이션 효과 끔(설정 › 접근성 › 시각 효과)을 따릅니다. 이때는 이동 없이 즉시 바꾸거나 페이드만 씁니다.
- 위치 · 크기 변환(transform)과 투명도만 움직입니다. 레이아웃을 다시 계산하게 하는 속성은 애니메이션하지 않습니다.

## 15. 접근성 (시각)

`Windows 지침:` 기본 화면에서 충분한 대비를 확보합니다. 고대비 모드를 낮은 가독성의 해결책으로 삼지 않습니다. 글자는 4.5:1 이상입니다. 적록 색약은 남성의 약 8%, 여성의 0.5%이므로 빨강 · 초록만으로 구분하지 않습니다. 대비 테마에서는 시스템 색 짝을 쓰고 색을 하드코딩하지 않습니다. 화면 배율 · 텍스트 크기 · 돋보기에서 확인합니다.

- 글자 대비는 4.5:1 이상입니다(비활성 · 로고 · 장식 글자는 예외). 위 토큰은 모두 계산해 두었습니다.
- 글자가 아닌 것(뜻이 있는 아이콘 · 입력칸 테두리 · 포커스 · 도면 선)은 3:1 이상입니다(WCAG 1.4.11).
- **색만으로 구분하지 않습니다.**
  - 상태: 색 + 아이콘 + 글자
  - 연결선: 색 + 선 모양 + (선택 · 마우스 올림 시) 이름
  - 선택: 외곽선 + 손잡이
  - 필수 입력: 라벨 뒤 `(필수)`
- 적록 색약(2형) 시뮬레이션에서 구분이 어려운 짝입니다(Machado 2009, ΔE00 — 작을수록 비슷하게 보임).

| 짝 | ΔE00 | 대책 |
|---|---|---|
| 서비스 ↔ 인터커넥트 | 0.9 (같은 색으로 보임) | 선은 모양이 다름(실선 ↔ 점선 · 긴 파선). 포트 칸은 툴팁 · 속성에 용도 글자 |
| 관리 ↔ 콘솔 | 1.4 | 포트 칸: 위와 같음 |
| 스토리지 ↔ 전원 | 6.0 | 둘 다 실선이고 굵기(1.75 ↔ 1.25)만 다름 → 범례 상시 표시 + 마우스 올림 시 이름 |
| 정상 ↔ 장애 | 9.6 | 아이콘 · 글자를 함께 표시 |

- Windows 대비 테마가 켜지면 화면 틀은 시스템 색 짝을 씁니다: `Window`/`WindowText`, `Highlight`/`HighlightText`, `ButtonFace`/`ButtonText`. `GrayText`는 비활성에만, `Hotlight`는 링크에만 씁니다. 도면의 용도 색은 유지하고 위 대책으로 구분합니다.
- 텍스트 크기(설정 › 접근성 › 텍스트 크기)를 150%로 올려도 잘림 · 겹침이 없어야 합니다. 글자가 든 칸의 높이를 고정하지 않습니다(5.2의 높이는 최소값).
- 키보드 포커스는 항상 보여야 합니다(5.3). 포커스 표시를 끄지 않습니다.
- 글자를 이미지로 넣지 않습니다.

## 16. 완료 전 점검

GUI 작업을 끝내기 전에 확인하고, 지키지 못한 항목은 보고합니다.

- [ ] 기준 창 1280 × 672에서 핵심 기능이 글자 라벨과 함께 보인다
- [ ] 강조색 버튼은 화면당 하나다
- [ ] 색 · 크기 · 간격 · 시간이 모두 이 문서의 토큰이다(크기 · 간격은 4의 배수)
- [ ] 글자 대비 4.5:1, 아이콘 · 테두리 · 선 대비 3:1 이상이다
- [ ] 색만으로 구분하는 곳이 없다
- [ ] 선택된 항목이 그 바탕에서 보이고(아래층은 덧칠 + 막대), 표 · 목록 행 전체를 상태 색으로 칠하지 않았다
- [ ] 누를 수 있는 요소마다 마우스 올림 · 눌림 · 포커스 · 비활성 상태가 있다
- [ ] 불러오는 중 · 비어 있음 · 오류 상태가 있다
- [ ] 쓸 수 없는 명령은 숨기지 않고 비활성 + 이유로 보여 준다
- [ ] 아이콘만 있는 버튼에 `이름 (단축키)` 툴팁이 있다
- [ ] 설명 문장을 UI로 바꿀 수 있는지 확인했고, 남은 문구는 한 문장이다
- [ ] 용어가 문서 · Windows 표준과 같다
- [ ] 라이트 · 다크 · 대비 테마, 화면 배율 100 · 125 · 150 · 200%, 텍스트 크기 150%에서 깨지지 않는다
- [ ] 애니메이션은 333 ms 이하이고, 애니메이션 효과 끔 설정을 따른다
- [ ] 투명 효과가 꺼져도 같은 화면이다
